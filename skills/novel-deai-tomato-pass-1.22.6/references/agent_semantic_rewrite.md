# Agent 语义精修闭环协议（L3 · agent 亲自判断 + 改写）

> 本 SOP 是 `scripts/semantic_scan.py` 候选输出的**下一步**：当本 skill 由 agent（LLM）执行时，
> 深层语义问题**不该只生成报告甩给用户**，而应由 **agent 亲自读上下文 → 判断越界 → 直接改写写回 docx → 标记待抽查**。
> 这正是突破"高级查找替换"的关键：**正则只负责"挖候选"，LLM 负责"理解 + 改写"**。

## 为什么必须 agent 亲自做

`semantic_scan.py` 的 A/B/C/D 类是**显式信号**（亲密 token 聚类 / 边界模糊词 / 多角结构词 / 未成年词），
能机械挖出，但仍有两大缺口正则补不上：

1. **暗示性留白**：一句"他望着她，没说话"本身安全，放在"已有暧昧对象 + 独处深夜"上下文就是多角信号；
   "贴着""气息"单看普通，聚类才构成亲密暗示——这类**依赖上下文**，机器无法拍板。
2. **软信号跨角色并列**：同场景里"他握着 A 的手，又想起 B 的笑"，没有越界词，但已构成"情感并列 / 多角暗示"，
   只有读完整关系设定才看得出来。

所以本层目标：**agent 用 LLM 语义理解，把"扫描器挖出的候选 + 上下文"变成"已改写的安全文本"，用户只抽查**。

## Agent 执行轮次（每次对话 3-5 章）

1. 跑 `semantic_scan.py <_过审版.docx> --out 语义风险报告.md`，拿到按章排列的候选（A/B/C/D 硬信号 + E 类中置信暗示）。
2. **先跑关系图谱定位多角**（见下节）：`relation_graph.py <_过审版.docx> --names <主要角色> --out 09_relation.md`，
   直接拿到"谁和谁在亲密语境共现、谁有多角预警"，不必自己从头通读梳理关系——这是把"人物关系处理"从纯人工降到"看图改"的关键。
3. **读上下文**：对 semantic_scan 候选 + relation_graph 预警角色，回原文读**前后 1-2 章**，确认人物关系设定（谁和谁是夫妻/知己/对手），避免误杀正常亲密或漏杀暗示。
4. **逐段判断 + 改写**（见下方"判定与改写"与"高置信自动改写规则"），直接改 docx 该段；改写后用 `[已改写·待抽查]` 标记该章处理进度（在对话里记，不必写进正文）。
5. 结构性重构（整章 / 整线多角）按 `manual_fix_sop.md` 场景 A，**涉及删情节 / 大改 / 动核心卖点时先 AskUserQuestion 确认**，不擅自动刀。
6. 全章过完，复跑 `semantic_scan.py` 确认该章 A/B/C/D 候选清零或仅剩"合理保留"，E 类经判断后要么改写要么标注"合理保留（非越界）"；复跑 `relation_graph.py` 确认多角预警角色已收束为单线。

## 用关系图谱定位多角（relation_graph.py 输出怎么用）

`relation_graph.py` 输出一张"亲密共现边"图 + **多角关系高置信预警**（亲密对象 ≥2 的角色）。
对预警角色，**agent 直接据此定向改写，无需再问用户"关系怎么处理"**——因为收束多角本就是过审硬要求：

- 预警角色 X 同时与 A、B 落入亲密语境 → 默认把 X 与其中一人定为夫妻/恋人，另一人改写为
  **合伙人 / 至交 / 对手**，删除两者间的亲密语境共现（见原则三、原则四）。
- 历史人物 / 群像里君臣、战友、亲族也会共现被报出，**agent 读上下文判定**：非暧昧的君臣/战友/亲族
  共现属正常，标注"合理保留（非多角）"；确实构成暧昧并列的才改写。
- 图谱没预警、但 semantic_scan 的 E 类（暗示性留白）命中的，仍按软信号规则读上下文判断。

> 关系图谱把"几十个角色里哪条暗线是多角"从 agent 的人肉通读，变成了**可枚举的预警清单**，
> 这是 v1.11.0 进一步降低"人物关系需人工判断"的核心手段。

## 高置信自动改写规则（进一步降人工：能不问就不问）

v1.10.0 要求 agent 改写处用户抽查；v1.11.0 进一步区分**高置信**与**需问**：

- **高置信 → agent 直接改写，不 AskUserQuestion**（改写保情节、不动核心卖点、不删整条线）：
  - 显式 C 类多角结构（脚踏两条船 / 左拥右抱 / 众星捧月 / 几房夫人）→ 收束为单配偶+合伙人；
  - 显式 A 类露骨身体细节 → 去 veil（原则一/二）；
  - 显式 B 类"说不清的关系"含糊暧昧 → 明确边界（原则三）；
  - 显式 D 类未成年负面 → 上调年龄 / 重构关系。
  - 这些改写的语义是确定的、可逆的（只换表述不删情节），agent 直接落盘即可，用户事后抽查。
- **仍需 AskUserQuestion（不擅自动刀）**：
  - 候选涉及**删整条感情线 / 改核心人设 / 动作者明确要保留的"多角爽点"**；
  - 改写会造成**情节逻辑断层**且无法无损补接；
  - 原稿多角 / 暧昧是**核心卖点且作者不愿改** → 如实告知需重新定位题材。
- 模糊 E 类（暗示性留白，无显式 token）→ agent 读上下文判断后改写或标"合理保留"，
  **不强制问用户**，但改写处列入"待抽查"清单供用户回看。

## LLM 判定规则（什么算越界，什么算安全）

### 显式信号（A/B/C/D，扫描器已挖出，重点看越界程度）
- **A 亲密聚类**：身体细节露骨 / 性暗示明显 → 必须去 veil（模板一/二）；普通的"贴近""气息"在单配偶情感递进里可保留。
- **B 边界模糊**：是否构成"多角导向"（同时暧昧两人）→ 是则明确边界（模板三）；单纯的"知己张力"可保留为人设。
- **C 多角结构**：脚踏两条船 / 左拥右抱 / 众星捧月 → 必须重构（单配偶 + 合伙人），优先级最高。
- **D 未成年负面**：未成年 + 多女 / 师生恋 / 低俗 → 必须改（年龄上调 / 关系重构），优先级最高。

### 软信号（E 类 + 纯语义理解，扫描器漏报或部分覆盖，靠 agent 读上下文判断）
以下情形**即使没有 A/B/C/D 显式 token**，也应判为"暗示性多角 / 暧昧越界"并改写：
- **独处 + 私密空间 + 对等亲密**：两人独处深夜 / 闺房 / 帷帐，且描写偏向"只有彼此"的亲密氛围；
- **跨角色情感并列**：同一场景 / 邻近段落里，主角对 A、B 均流露超出友谊的在意（"握着 A 的手，又想起 B"）；
- **情感独占暗示留白**：用"只对你 / 只有我们 / 旁人不知"制造排他性亲密，且无明确单配偶关系背书；
- **时间线重叠的暧昧**：与甲未断、又与乙亲近，中间无清晰分手 / 关系闭环。

反之，**不构成越界**（保留）：单配偶情感递进、已明确夫妻/恋人关系的正常亲密、兄弟/知己间的"只对你说机密"（无暧昧语境）。

## LLM 理解力校准：同一句话，上下文不同判定不同

> **本层效果的天花板 = 大模型的理解力。** 扫描器 A/B/C/D 能机械兜底；但**模糊暧昧、人物关系的微妙处，机器扫不出来，全靠 LLM 读上下文判断**。模型越强、你喂的上下文（前后 1–2 章）越足，判断越准。下面用"同句异判"演示 agent 该怎么读上下文——这也是你抽查时的对照标尺：发现 agent 误杀正常亲密或漏杀暗示，直接指出来，它据此修正（人机协作，不是黑盒）。

**例 1：「他替她拢了拢披风，指尖擦过她手背」**
- 上下文甲（安全，保留）：前文已明确二人是夫妻 / 恋人，且全书单配偶 → 普通亲密描写。
- 上下文乙（越界，改写）：上一章他刚对林月也有同样举动且未定关系 → 构成"跨角色情感并列 / 多角暗示"，需收束为单线。

**例 2：「只有我们两个人知道的事」**
- 安全（保留）：兄弟 / 搭档间说机密，无暧昧语境 → 正常。
- 越界（改写）：用"只有我们"制造排他性亲密，且两人无单配偶关系背书 → E 类留白，需改写破除独占暗示。

**例 3：「他望着她，没说话」**
- 安全（保留）：单配偶情感递进里的安静时刻。
- 越界（改写）：他刚与另一女主亲密，转头又这样望她 → 多角信号，需按原则四删并列暗示。

**校准要点**：下"保留 / 改写"结论前，先确认三件事——① 两人当前关系是否已明确单配偶；② 邻近段落 / 章节里主角是否对其他人也有同等亲密；③ 有无清晰的关系闭环（分手 / 定情）。三点齐了再判，避免凭单句误判。

## 四个改写原则（对应 before/after 范例）

### 原则一：去 veil（剥离露骨身体细节，保留情感）
- **before**：他的手贴着她的腰，气息拂过耳畔，她浑身一颤，潮红爬上脸颊。
- **after**：他忽然退了半步，别过脸去，声音哑了几分："……别这样。"

### 原则二：情感克制（"意乱情迷"转"内心波动"）
- **before**：两人贴近，唇几乎相触，她意乱情迷，心跳如鼓。
- **after**：两人之间的距离近得能听见彼此的呼吸，她攥紧了衣角，一时不知该进该退。

### 原则三：明确关系边界（破"多角暧昧"含糊）
- **before**：他对她，比对谁都不同，那种说不清的关系，连自己都分不清是朋友还是别的。
- **after**：他待她确有几分特别，可那份特别止于知己——他心里清楚，越界便是对两个人的不负责。

### 原则四：删暗示留白（把"跨角色情感并列"转为单线）
- **before（暗示性，无显式 token）**：夜深了，他替苏婉拢了拢肩上的披风，指尖无意擦过她手背；回到书房，案上摊着林月昨日留下的诗稿，他盯着那行字，半晌没动。
- **after**：夜深了，他替苏婉拢了拢肩上的披风，嘱咐她早些歇着。回到书房，他摊开明日要议的文书，把心思都放在了实务上——儿女情长，他早吩咐自己先搁在一边。
- **改完判定**：删掉了"又想起另一个人"的并列暗示，把情感收束到单一关系 / 事业线，消除多角导向（E 类清零）。

### 原则五：多角收束为单线（relation_graph 高置信预警直接改，不问）
- **before（relation_graph 预警：男主同时与苏婉、林月落入亲密语境）**：
  苏婉斟了杯茶递来，指尖温软；林月倚在门边，朝他眨了眨眼，那神态惹得他心猿意马。
- **after**：苏婉斟了杯茶递来，仍是副沉稳管家的做派；林月倚在门边报账，说的是下月的采买开销，公事公办，并无半分逾矩。
- **改完判定**：把"苏婉（暧昧）+ 林月（暧昧）"双线收束——苏婉定位为得力助手、林月定位为账房，删除两人对男主的亲密信号，多角导向（C 类角色级预警）清零，不删情节、不动核心卖点，属高置信直接改写。

## 何时必须问用户（不擅自动刀）

- 候选涉及**删整条感情线 / 改核心人设 / 动作者明确要保留的"多角爽点"** → 先 AskUserQuestion 确认重构方向（默认"单配偶 + 合伙人"）。
- 改写会造成**情节逻辑断层**（如删了过渡段导致前后不接）→ 问用户要"保情节连贯"还是"保过审优先级"。
- 原稿多角 / 暧昧是**核心卖点且作者不愿改** → 本 skill 无法帮你过审，如实告知用户需重新定位题材（如改纯事业线）。

## 复扫确认（全局判定）

- `semantic_scan.py` 复扫：全书 A/B/C/D 候选趋近 0；E 类经判断后要么改写、要么标注"合理保留（非越界）"，不得遗留"疑似越界但未处理"。
- 全书不存在"多角围一人"结构（C 类全书级告警应为 0）。
- 未成年负面（D 类）全书为 0。

> ⚠ 本协议让 agent 从"生成报告的人"变成"改写的手"。但**最终责任在用户**：① agent 改写处用户须抽查，尤其 E 类软信号判断（误杀正常亲密 / 漏杀暗示）需用户把关；② **模糊暧昧 / 人物关系的判定准不准，取决于大模型的理解力**——这是本层的天花板，不是 bug。发现判断偏差，直接告诉 agent，它读更多上下文后修正。③ **AI 味消除效果因书而异，本流程不承诺单本书 100% 过审，但以"常规文本至少 90% 以上过审"为设计目标**——深层暧昧暗示等模糊地带配合高置信自动改写 + 你抽查可以完全避免；它是得力的辅助工具，愿意配合抽查的用户，收益最大。
