# 种马后宫文 → 过审 重构方法论

## 核心判断
番茄对"**种马后宫文**"是**零容忍**：书名 + "多女共侍一夫 / 多恋暗示"的结构性设定，光改几个词没用，必须**重构人物关系**。已验证可行的重构方向（按用户拍板）：

| 方向 | 做法 | 过审把握 |
|------|------|----------|
| **单配偶 + 三合伙人**（采用） | 男主只与一人是夫妻，其余女性改为创业合伙人 / 至交姐妹。删除多妻、上床、情人、新娘、三个新娘等暗示 | 最稳，改动最大 |
| 纯事业线，感情极简 | 四女全为公司同事，亲密关系大幅弱化 | 最安全，情感戏损失大 |
| 仅改书名 + 换词（不推荐） | 保留四女围绕男主的暧昧结构 | 大概率仍判"种马后宫文"驳回 |

## 重构映射的两条技术路线
1. **批量子串替换（bulk）**：对精确原文片段做"旧→新"替换。适合：书名、章节标题、明示多妻/多恋句、身体物化描写、去浪漫化尾句。
2. **整章替换（chapter_swaps）**：某章整体违规（如多妻婚礼），整章删除旧正文、插入合规新正文。需指定章标题与下一章标题作为边界。

## 默认映射文件 `example_map.json` 结构
```json
{
  "title_old": "重生2026：开局四个绝色老婆，我靠AI赢麻了",
  "title_new": "重生2026：我靠AI赢麻了",
  "bulk": [ ["旧子串", "新子串"], ... ],
  "chapter_swaps": {
    "第四十章 三驾马车": {
      "next": "第四十一章",
      "body": ["合规新正文第1段", "..."]
    }
  }
}
```
本文件是《重生2026》的**可用工作样例**（114 条 bulk + 第40章整章替换）。换别的书时，必须重建自己的 map。

## 适配到另一本小说的步骤

**第 0 步（先跑向导，不从零手建）**：
```
python scripts/build_map_wizard.py <新书.docx> --map draft_map.json --out 扫描报告.md
```
向导自动产出：书名识别、通用安全替换（直接可用）、触发词候选（带上下文例句和建议词）、
整章违规候选、高频说话人清单。在草稿基础上按下面 1-5 定稿映射，工作量从"从零写 114 条"
降为"确认向导候选 + 补人物专属替换"。

1. 通读，锁定"唯一的配偶"（如原设定里的正妻/明媒正娶者），其余女性角色列清单（参考向导 speakers）。
2. 把每位非配偶女性重新定性为：合伙人 / 姐妹 / 挚友 / 干妈，并据此改写涉及"爱/嫁/名分/上床"的句子。
3. 确认向导 candidates 里的触发词替换（上床、情人、新娘、三妻四妾、后宫、种马、名分、白月光、暧昧等），定稿后挪入 bulk。
4. 找出整章违规点（求婚、多妻婚礼、复数 intimacy，向导会给出候选章），用 chapter_swaps 整章重写。
5. title_new 必填，运行 `reframe_novel.py in.docx out.docx --map 定稿map.json`。

## 必须人工扫尾的残留（脚本覆盖不到的语义层）
脚本跑完后，仍会残留**语义层**多女信号，需读原文逐段手改：
- "名分" 在"不是来争名分""不需要名分"等对话里的剩余变体。
- "皇帝 / 脚踏四条船 / 左拥右抱 / 齐人之福 / 众星捧月"等比喻。
- 非配偶角色对男主的"爱/喜欢/征服/唯一"表白框架 → 改为"欣赏/伙伴/家人"。
- 非配偶角色的亲吻/拥抱 → 改为拍肩/碰脸颊/握手。
- 身体物化（深 V、事业线、腿、腰臀的过度描写）→ 中性化。

## 验证清单（每次重构后必跑）
- 书名属性已改；章节数 / 全书完 结构完好。
- 硬伤触发词合计趋近 0（允许 ≤5 处需人工确认的无害残留）。
- 抽取正文肉眼过一遍第 35/40/47 类深章，确认无"共侍一夫"潜台词。
