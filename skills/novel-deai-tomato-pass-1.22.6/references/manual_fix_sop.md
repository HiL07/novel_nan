# 人工处理 SOP：机器做不了的，人怎么改、改到什么程度算完

> 本 skill 的脚本是**文本级规则引擎**，能处理替换、统计、定位、以及**部分自动改写**。
> 自 v1.6.0 起，`auto_rewrite.py`（L2.5 自动改写层）已接管五类**可安全自动修复**的机械型 AI 味
> （情绪直陈→行为微描写、陈词比喻替换、套路转场轮换、扩展填充词、对话标签去烂副词）；
> 自 v1.7.0 起，`pipeline.py` 把提取/向导/重构/L1/L2/L2.5/L2复评/评估检测的机械流程串成一条命令，
> 并产出 `99_PIPELINE_SUMMARY.md` 汇总"哪些已自动搞定、哪些仍需你确认"。
> L3 精修（场景 D 的声纹/同构/章尾）也有了可复用的重写模板，见 `references/llm_rewrite_sop.md`。
>
> 以下**仍必须人工**的五类判断它做不了——遇到不是"脚本没写好"，而是语义/艺术级问题，
> 按本 SOP 处理，做完有明确判定标准，不会"改了又不知道改完没有"。

## 场景 A：语义层多女信号（脚本扫不出的"潜台词"）

**机器为什么做不到**：`上床` 这类词能替换，但"他这一生，终究亏欠了她们三个"这种句子，
没有任何触发词，替换规则无从下手；`名分`、`皇帝` 虽在词表里，但替换后语义是否干净，
需要人判断。

**人工步骤**：
1. 抽出全文，逐章回答：**"男主的配偶到底是谁？"** 只允许 1 个答案（默认正妻/明媒正娶者）。
2. 其余每位女性角色，明确重新定性：合伙人 / 姐妹 / 挚友 / 干妈，写进人物关系表（见场景 B）。
3. 凡涉及"爱 / 嫁 / 名分 / 上床 / 亏欠 / 舍不得她受苦"的句子，按新定性改写：
   - "亏欠她们三个" → "亏欠当年帮过他的三个挚友"
   - "她等他给个名分" → "她等他把话说开"
   - "皇帝般的日子" → "说一不二的日子"
4. 重点查**章节末尾**和**情绪高潮段**——多女信号最爱藏在煽情收尾里。

**做完的判定**：把人物关系表给一个没读过原文的人看，他能说出"男主只对一个人有男女之情"。

## 场景 B：人物关系连贯性（全书一致性）

**机器为什么做不到**：替换是逐句的，上一章"合伙人"、下一章又写成"恋人"，脚本发现不了。

**人工步骤**：
1. 建一张表：`角色 | 新定性 | 出现章节 | 是否有越界表述`。
2. 每改完一章，对照表格检查该章出现的所有女性角色表述是否与定性一致。
3. 全书过完后，**按角色汇总**搜索一遍（如全文搜"她"指向林薇的段落集中重读）。

**做完的判定**：人物关系表所有"越界表述"列为空；任意角色的全部出场段落，定性统一。

## 场景 C：剧情逻辑与删改决策（"删了这章有影响吗"）

**机器为什么做不到**：`eval_fix_check.py` 只能标出"章节字数异常/对话占比超标"，
但一章是水文还是铺垫，需要人判断剧情贡献。

**人工步骤**：
1. 对每章写一句"**本章推进了什么**"（一句话，写不出来的章就是水文候选）。
2. 水文候选章判定：删掉它，后面的剧情是否依然成立？
   - 成立 → 删 / 合并进相邻章；
   - 不成立但信息量少 → 压缩到 500 字内并进相邻章；
   - 与主线无关但有趣 → 移到番外。
3. 改完按 `tomato_eval_fix.md` 的硬性基础复查格式。

**做完的判定**：每章都能写出推进句；不存在"删了不影响剧情"的章。

## 场景 D：艺术判断（听感 / 节奏 / 声纹）

**机器为什么做不到**：`deai_deep_report.py` 能告诉你"第三章对话标签 18 次、口头禅趋同"，
但"读起来像不像真人写的"只有人耳能判。

**人工步骤**：
1. L3 精修每轮改完 3-5 章后，**出声读一遍对话**（默读也算）。
2. 判定问题：不看角色名，能否分出是谁在说话？分不出 → 该角色缺口头禅/语气差异，按
   `references/llm_rewrite_sop.md` **模式一（跨角色声纹）** 模板给每人设语癖并改写其对话。
3. 读感检查：连续 3 句以上相同句式（"他X道"）→ 按 **模式二（段落同构）** 打散；
   章尾连续同类收尾 → 按 **模式三（章尾套路）** 换成本章专属动作。
4. 全书 MUST 清零后，**随机抽 3 章**做最终听感抽查（不要只抽自己改得顺的章）。

**做完的判定**：抽查 3 章，每章读对话能分人；没有连续 3 句同构句；情绪靠动作/对话表达而非直陈。

## 场景 E：封面 / 版权 / 时政（脚本根本不碰的三样）

**机器为什么做不到**：脚本不读图片、不连版权库、不碰时政库——这是刻意边界，
见 `references/cover_copyright_checklist.md`。

**人工步骤**：交付前按清单逐项确认（封面 8 项 + 版权 6 项），用提问方式让用户逐项确认，
未确认项**加粗**写进交付警告。版权问题的后果量级 > 内容驳回，不能省。

**做完的判定**：清单全项勾选；有未确认项时，交付警告中明确列出并加粗。

## 兜底决策：改不动怎么办

| 情况 | 处理 |
|---|---|
| 单章重写后仍过不了 | 整章删掉，用 200 字概述+新钩子衔接，别死磕 |
| 结构级硬伤（整本书就是后宫文） | 建议用户换方向：纯事业线 / 大幅弱化感情线，不要只换词 |
| 残留无害触发词 ≤5 处 | 允许保留，但交付说明里逐条列出原因 |
| 人工判断拿不准 | 先跑 `tests/run_tests.py` 确认脚本层没回退，再回到本 SOP 对应场景 |

## 一句话总纲

**脚本负责"可枚举的"，人负责"可感受的"**——凡是能列出规则交给脚本的，别让人做；
凡是需要判断、感受、品味一致性的，别指望脚本——按上面五类对号入座，做完有判定，不背锅。
