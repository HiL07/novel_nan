# 变更日志（CHANGELOG）

本文件记录 `novel-deai-tomato-pass` 每次版本的能力增量、参数变化与不兼容点，对应 TRACE 评测的 **Convention（规范性）** 维度——便于开发者追溯演进、判断升级影响。

版本号遵循语义化：`主.次.修订`。涉及能力增删或参数重命名记为次版本（如 1.10→1.11）；纯文档/定位调整也 bump 次版本以便评测与发布台账对齐。

---

## 1.22.0（2026-09-08）
- **触发决策树 + 命令速查卡（A·触发方式，攻 4.5）**：SKILL.md「何时使用」新增 **「30 秒速判（决策树）」表**——把 6 类场景直接映射到「用不用 / 走哪一步」（✅用 / ⚠️部分 / ❌不适合），并新增**命令速查卡**（5 条高频命令一行一条）。回应评测"缺少快速参考卡片或触发决策树帮助用户快速匹配场景"的具体建议；决策树明确列出「想要一键全自动、零人工零抽查 → ❌ 不适合」，不诱导误用。
- **开跑前预检（R·异常处理，攻 4.3）**：新增 `scripts/precheck.py` 做**事前校验**（与 `errkit` 的事后异常翻译互补）——按序检查文件存在 / 不是目录 / 是 .docx（.doc 与 .txt 分开提示"另存为"）/ 空文件 / 过大(仅警告) / 有效 zip / 含 word/document.xml / 可读(被占用) / 依赖 python-docx(阻塞)·Pillow(警告)，每项错误均为「⚠️ 标题 / 原因 / 怎么修」三段式；`pipeline.py` 入口内置预检，阻塞问题直接终止且**不改动任何文件**（退出码 1），不再跑到一半才抛 Python 原生异常。可单独跑 `precheck.py <书.docx>` 做体检。
- **测试 18 → 20**：新增 `test_19_precheck`（不存在 / 坏 docx 均 exit 1 且给「怎么修」，正常文件 exit 0 报"预检通过"）与 `test_20_trigger_decision_tree`（SKILL.md 含决策树与速查卡，且标明「不适合」场景）。
- 兼容性：无既有参数变更；新增 `precheck.py` 一个脚本与 SKILL.md 两个表格，1.21.0 用户可直接升级。
- 注：本版改动依据的平台评测为 **2026-09-02 针对 v1.17.x（versionId 282487）的旧快照**；v1.20.0 / v1.21.0 的改进均未被该评测反映，其分数不代表当前版本真实水平。

## 1.21.0（2026-09-07）
- **去AI机械层改写效果量化（E·输出准确性，攻 4.5 短板）**：`scripts/deai_humanizer.py` 改写前后各复用 `wiki_signs_scan` 的 AI 味浓度分算法算一次，输出「AI 味浓度分 前→后 + **消除率**」；新增 `--report` 参数写出 `deai_report.md`（改写段落数 / 消除率 / 仍残留的高频信号 Top3 供 L3 定向精修；浓度分若未降反升会明确告警）。把"改得怎么样"从"只报改了几段"变为**可验证的量化证据**。
- **推荐评估就绪度自检（E·创造力与增值 + 内容完整度）**：新增 `scripts/eval_readiness.py`，在 `eval_fix_check` 逐章清单之上补**宏观总览**——按字数门槛(30)/章节健康度(20)/开篇钩子(20)/AI味健康度(15)/对话健康度(15) 算 **0-100 综合就绪度**，产出 `12_eval_readiness.md`（五维得分雷达 + 最需补的短板清单 + 分级建议）。对齐 `references/tomato_80k_evaluation.md` 的 8 万字硬门槛；日更稳定性（连续3天≥4000）、验证期留存率**无法从文档判断**，单列「需后台自查」段不谎报。
- **pipeline 集成**：L1 去AI步骤传 `--report` 产出 `deai_report.md` 并解析消除率；新增第 8.5 步 `eval_readiness` 产出 `12_eval_readiness.md`；汇总报告 `99_PIPELINE_SUMMARY.md` 新增「推荐评估就绪度」段与消除率行，产出清单同步两项，控制台亦打印。
- **测试 16 → 18**：新增 `test_17_deai_elimination_rate`（断言浓度分下降 + 消除率输出 + `deai_report.md` 生成）与 `test_18_eval_readiness`（小字数书就绪度低 / 达标健康书就绪度高，两端断言）。
- 兼容性：无既有脚本参数变更；`deai_humanizer.py` 由位置参数改为 argparse（原 `python deai_humanizer.py in.docx out.docx` 用法完全兼容，新增可选 `--report`）。
