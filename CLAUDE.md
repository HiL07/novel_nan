Project guidance for AI coding assistants (Claude Code). Read this before generating or modifying code.

## 1. Project Overview

**nan_novel** is an AI-assisted **novel generation** system. Users upload and manage novel/manuscript source files; a Python AI service extracts and analyzes the text and fine-tunes remote large language models (**QLoRA / Hugging Face**) to power novel generation.

The system consists of three components:

| # | Component | Role | Status |
|---|-----------|------|--------|
| 1 | **Frontend** (`frontend/`) | Vue 3 + Vite SPA — file upload & management UI | Implemented |
| 2 | **Java backend** (`backend/`) | Spring Boot — **file management is the base framework**: upload-to-disk, metadata in SQLite (`data/nan_novel.db`), download/preview APIs | Implemented |
| 3 | **Python AI backend** (`python-service/`) | FastAPI — article/content extraction, text analysis, local model management + LoRA/QLoRA style fine-tuning (Hugging Face) | Extraction + **local** fine-tuning implemented; remote inference/training planned |

```
Browser (Vue3/Vite, :5173)
        │  HTTP
        ▼
Spring Boot (:8022) ─────► SQLite data/nan_novel.db (metadata) + data/upload/ + data/extract-results/
        │  HTTP  ▲ GET /api/file/preview/{id}
        ▼        │
Python FastAPI (:8021) ─────► OpenAI-compatible LLM (default DeepSeek; configurable, e.g. local llama.cpp)
                        ├───► local GPU: Transformers + PEFT inference / LoRA-QLoRA training (models/)
                        └───► remote inference / training (planned)
Browser ──(本地模型 page, direct)──► Python /api/local/**
```

## 4. Java Backend Conventions (`backend/`)

### Commands

```bash
mvn spring-boot:run     # run on http://localhost:8022 (requires JDK 17)
mvn spring-boot:run -Dspring-boot.run.arguments="--server.port=8012 --ai.service.url=http://localhost:8011"   # test instance
mvn clean package       # build jar (Lombok excluded from the fat jar)
```

### Layering & package rules (`com.example.file`)

- `controller` → `service` → `mapper` → `entity`. Cross-layer calls are not allowed.
- New feature = full set: `entity` (`@TableName`, `@TableId(type = IdType.AUTO)`) → `mapper extends BaseMapper<T>` (no hand-written SQL unless necessary) → `service` → `controller`.
- **Constructor injection only** (no field `@Autowired`); use `@Data`/Lombok on entities and DTOs.
- Use SLF4J `LoggerFactory` loggers; log exceptions with context, never expose stack traces to clients.

### HTTP & response conventions

- All JSON endpoints are under `/api/**` and **must return `Result<T>`** (`com.example.file.common.Result`):
  - Success: `Result.ok(data)` → `{ "code": 0, "message": "ok", "data": ... }` — **code `0` means success**.
  - Failure: `Result.error(code, message)`.
- Throw `BizException(code, message)` for business errors (e.g. 404 not found); controllers translate it to the proper HTTP status.
- Binary endpoints (download/preview) return `ResponseEntity<byte[]>` with correct `Content-Type` and `Content-Disposition` (`attachment` vs `inline`).

The 文件管理 dialog loads 100k chars at a time (scroll / 加载更多) — rendering a whole multi-MB novel froze the page |

### Novel extraction API (`NovelExtractController`)

| Method & path | Purpose |
|---------------|---------|
| `POST /api/novel/extract/{fileId} {materials?, model?}` | Create an async extraction task for a txt/md/docx/pdf file; returns the task (`QUEUED`). `model` = `{source: api, configId?}` (any **VERIFIED** config, used for this task only — the active config is not changed; empty = active) or `{source: local, baseId, chunkChars?}` (in-app 本地模型, no tokens; `chunkChars` 1000–6000, default 2500) |
| `POST /api/novel/extract/{id}/pause` | 暂停 a QUEUED / RUNNING task → Python stops before the next chunk → **INTERRUPTED** 「已暂停」 (checkpoint kept) |
| `POST /api/novel/extract/{id}/cancel` | Cancel a QUEUED / RUNNING / INTERRUPTED task (running → Python stops first) → FAILED「已取消」. Only cancel moves a task to 提取失败 |
| `POST /api/novel/extract/{id}/resume` | **继续** an INTERRUPTED task: if the Python job (`job_id`) is still queued / running / succeeded (Java restarted) it is adopted and polled; otherwise re-submitted with the stored `options` (`{model, materials}`, column `novel_extract.options`, no key) and the same checkpoint key `e<id>` — finished chunks / blocks / cards are not redone |
| `POST /api/novel/extract/delete {ids}` | Delete **FAILED** tasks only (others skipped) and their Python checkpoints → `{deleted, skipped}` |
| `GET  /api/novel/extract/list` | Tasks without `result`, `create_time` descending; each has `pendingCount` (PENDING candidates of that task, `MaterialService.pendingCountsByExtract`) |
| `GET  /api/novel/extract/{id}` | Task detail; `result` is the extraction JSON string (chapters, characters, style); unfinished tasks carry `checkpoint` (`{exists, stages, running}` from Python, null when unreachable) and `options` |
| `GET /api/novel/extract/split/{fileId}` · `GET /{id}/live?since=N` · `GET /file/{fileId}/chapters/{index}/text` | 分章预览 (Python `split-preview`, same rules as extraction → `{chars, total, chapters[{index (1-based), title, kind, chars}], warnings}`); **逐章** while extracting → `{status, progress, message, live: {exists, range, chapters? (since=0), rows[{ci, status done\|failed\|partial, card, entities, threadOps, error}], next, current, running}}` or `{finished: true}` once the result file exists (the UI then builds the same rows from the result); one chapter's text by file + whole-book index (0-based) → `{index, title, kind, text, total}` (works before a task exists) |
| `POST /api/novel/extract/{id}/result {chapters[], characters[], style, …}` | Save a hand-edited result (whole JSON replaced; must contain `chapters`; SUCCEEDED tasks only). Rewrites the file via `ExtractResultStore.write`, updates `result_size` / `result_sha256` / `chapter_count`, adds `editedAt` to the JSON; if the DB update fails the old file is written back |

- Table `novel_extract` (DDL `sql/novel_extract.sql`, auto-created via `spring.sql.init`): `id`, `file_id`, `file_name`, `status` (QUEUED/RUNNING/INTERRUPTED/SUCCEEDED/FAILED), `options` (submit JSON, added by `SchemaMigrations`), `progress`, `message`, `job_id`, `result_path`, `result_size`, `result_sha256`, `word_count`, `chapter_count`, `candidate_count`, `create_time`, `update_time`. **The full result JSON is not stored in the DB**: `ExtractResultStore` writes `data/extract-results/<id>.json` (temp file → fsync → atomic rename, SHA-256 recorded) before the row is marked SUCCEEDED (write failure → FAILED, no path; DB failure → file removed). `GET /api/novel/extract/{id}` reads it back into the transient `result` field (same API shape); a missing / tampered / out-of-tree file yields `result: null` and an explanation appended to `message`.
- `NovelExtractService` runs tasks on a single background thread using the chosen model (提取工作区 `ExtractOptionsForm` 「提取模型」: 大模型 = a verified config, local hosts tagged 「本机 · 免费」, or 本地模型 + 分段字数 + time estimate; remembered in localStorage `nan_novel.extract.model`; snapshot taken at submit; no config → 400). Python 400 `detail` (e.g. GPU busy) is shown in the task message: submits to Python `POST /api/extract/jobs`, polls `GET /api/extract/jobs/{jobId}` every 3s, and persists progress/result. **Any error while running** (Python unreachable / restarted / job failed / 400 rejection) and tasks left QUEUED/RUNNING at a Java restart become **INTERRUPTED** (stay under 提取中, 继续 or 取消); only tasks without stored `options` (pre-migration) become FAILED, and a result-file write failure is FAILED. Every extraction path checkpoints: chapter-only per chunk (`chunks.jsonl`), entity recording per block (`pass1|pass2.jsonl`, below); Python refuses a second job on a checkpoint key that is still in use. Every submit sends `resumeKey: e<taskId>`; after the result is saved Java deletes the checkpoint (`POST /api/extract/checkpoints/{key}/delete`). A task that recorded entities ends with 「提取完成：N 个实体、M 条事实（丢弃 x 条对不上原文的），可以「整理卡片」」 and creates **no** candidates.
- Python URL: `ai.service.url` in `application.yml` (default `http://localhost:8021`).

| Method & path | Purpose |
|---------------|---------|
| `GET  /api/ai/model/list` | Configs, active first. `apiKey` is write-only; responses carry only `apiKeyMasked` |
| `POST /api/ai/model/fetch-models {id?, baseUrl, protocol, apiKey?}` | 「获取可用模型」: Python `POST /api/models/list` (`llm_client.list_models`: OpenAI `GET {baseUrl}/models`, Anthropic `GET {baseUrl}/v1/models`) → `{ok, models[{id, name}], message}` (404 = the service has no list endpoint, add names by hand); blank `apiKey` + `id` = the stored key |

Changing `baseUrl`/`model`/`apiKey`/`protocol` → `UNVERIFIED` + inactive. `providerType` `preset` (第三方模型提供商, `providerId` = preset key from `api/aiModel.js#PROVIDER_PRESETS`) / `custom` (自定义模型 API: `providerId` required, `[A-Za-z0-9][A-Za-z0-9._-]{0,63}`, unique among custom rows), `protocol` `openai` / `anthropic`, `models` = 模型目录 (deduped, ≤1000, the chosen `model` always included first) |

| `POST /api/ai/model/{id}/activate` | Only `VERIFIED` configs; deactivates all others |
| `POST /api/ai/model/{id}/delete` | Delete |

- Table `ai_model_config` (DDL `sql/ai_model_config.sql`): `id`, `name`, `provider_type`, `provider_id`, `protocol` (null = openai), `models` (JSON, `JacksonTypeHandler`; these four added by `SchemaMigrations` on old DBs — old rows have no type and the page guesses preset by base URL), `base_url`, `model`, `api_key`, `concurrency` (1–8), `status` (UNVERIFIED/VERIFIED/FAILED), `verify_message`, `verified_time`, `active`, `create_time`, `update_time`.
- Default model (`ai.default.*` in `application.yml`: DeepSeek, `https://api.deepseek.com`, `deepseek-chat`) is seeded on first start when the table is empty, then auto-verified in the background. Its key comes from `ai.default.api-key` in **`backend/application-secret.yml` (git-ignored, imported via `spring.config.import`)** or env `DEEPSEEK_API_KEY`. Never put API keys in tracked files or logs; don't log AI-service error bodies (422 echoes can contain the key).
- CORS is GET/POST only, so update/delete endpoints use POST.
- JSON endpoints use `common/ResultResponses.handle(...)` to map `BizException` → HTTP status + `Result.error`.
- JDK 17 on Chinese Windows defaults to GBK: always pass an explicit charset when converting bytes ↔ String (and `spring.sql.init.encoding: UTF-8`).

### Python environment API (`PythonEnvController`)

Detection runs **in Java**: `PythonEnvService` executes the selected `python.exe` with the stdlib-only probe `src/main/resources/python/env_probe.py` (version, arch, venv/conda, `torch.cuda` + GPU/VRAM, and status of every line in `python-service/requirements.txt` / `requirements-local.txt`). The backend therefore never depends on the Python being checked.

| Method & path | Purpose |
|---------------|---------|
| `GET  /api/python-env/discover` | `system` (PATH `python`, Store `WindowsApps` stub flagged/skipped), `conda` (`conda env list --json`), `venv` (default `python-service/.venv`), `anyUsable`, `miniconda` guide links (official + Tsinghua), `current` |
| `GET  /api/python-env/conda/envs?condaPath=` | Conda envs; `condaPath` = install dir or `conda.exe`; blank → `CONDA_EXE` → PATH → common dirs |
| `GET  /api/python-env/browse?path=` | Server-side file browser for the "浏览" button (dirs + `python*.exe`; blank = drive roots) |
| `POST /api/python-env/check {envType: SYSTEM\|CONDA\|VENV\|CUSTOM, pythonPath, condaRoot?, condaEnv?}` | Run the probe (≤150 s). `level` OK / WARN / ERROR + `problems[{level,title,detail,fix}]`. ERROR = invalid path, Store stub, Python < `python-env.min-version` (3.10), 32-bit, or missing **service** deps. WARN = torch/CUDA/local deps missing. OK/WARN → saved as the active row in `python_env` and written to `python-service/.python-env` |
| `GET  /api/python-env/current` | Active config + `lastResult`, `exists` |

- `python-service/.python-env` (git-ignored): one line, the interpreter path, written in the **native charset (GBK)** so `start.bat`'s `set /p` reads Chinese paths correctly; re-synced from the DB on every backend start. `start.bat` uses it for the AI service, falling back to `python-service/.venv`.
- Project root is auto-detected (works when started from `backend/` or the repo root); override with `python-env.project-root`.

Reusable creative material extracted from novels or added by hand. **Nothing enters `material` without explicit confirmation**: AI output is stored as `material_candidate` (PENDING) and only "保存" turns it into a material.

### Novel crawl API (`NovelCrawlController`, `/api/novel/crawl/**`)

Fetches web novels and stores them as normal **txt files in file management**, so they can be extracted like uploads. Re-implementation of the idea in `copybook/` (scrapy spider for the now-dead quanshuwang.com: hardcoded XPath, whole-site crawl, writes Django's sqlite): configurable rules, rate-limited, Java is the only DB writer. **Two modes**, chosen by `options.mode` (default `book`) and surfaced as a switch on the crawl page:

- **`book`** — one table-of-contents URL → one txt (the original behaviour).
- **`site`** (UI: 全自动) — the book list comes from a **site catalog** built with an AI-learned rule (see *Auto crawler* below); Java crawls **one book at a time** through the same single-book pipeline, so each novel becomes its own txt (`novel_crawl_book` rows). One Java task, N Python jobs. (The old copybook-style `/discover` endpoint was removed; old site tasks still retry / resume from their stored book list.)

- `NovelCrawlService` runs tasks in **per-home lanes** (`enqueue` / `laneBusy`, key = `homeOf(url)`): tasks of the same home page — single-book and 整站 alike — run one after another (a waiting task's message says 「同一网站（host）还有任务在抓」), different homes run in parallel on a cached pool. Site mode repeats that per book, aggregating chapter/word counts and progress (`bookDone/bookTotal`); cancel sets a flag, cancels the in-flight Python job, and marks not-yet-started books CANCELLED. Python 4xx messages are passed through as 400 (no API key involved).

### File storage rules

- Root dir from `file.storage.path` in `application.yml` (`${app.data-dir}/upload`, i.e. `data/upload/`). Uploads are written to `<name>.part` then atomically renamed; if the DB insert fails the file is deleted. `read()` rejects storage paths that resolve outside the upload root.
- Stored filename = **UUID without dashes** + lowercased extension; date-partitioned as `yyyy/MM/dd/`.
- DB stores only the **relative** `storage_path`; always resolve against the configured root and normalize paths (path-traversal safe).
- Upload limit: 50 MB per file / per request (see `application.yml`).
- **Database (SQLite)**: `jdbc:sqlite:${app.data-dir}/nan_novel.db` (WAL, `busy_timeout=10000`, Hikari pool 4). Only Java opens it. `app.data-dir` = `DATA_DIR` or auto-detected `<repo>/data` (`DataDirEnvironmentPostProcessor`); `common/DataPaths` resolves and traversal-checks paths under it. LocalDateTime is stored as text `yyyy-MM-dd HH:mm:ss` (`LocalDateTimeTextTypeHandler`); booleans as 0/1; no foreign keys (logical links only, handled in code). Pagination dialect `DbType.SQLITE`. Tables are auto-created at startup from the per-table scripts; `sqlite3 data/nan_novel.db < backend/src/main/resources/sql/init.sql` creates them manually. **Store metadata only** — large content (novel text, full extraction results) goes into files under `data/`. **When adding or changing a table, update both its per-table script and `init.sql`.**
- `file` table columns, derived from `FileInfo`: `id` (auto increment), `file_name`, `storage_path`, `file_size`, `content_type`, `file_ext`, `chapter_count`, `create_time`. `chapter_count` (txt/md only; `service/ChapterCounter` = same heading rules as Python `text_loader.split_book` / `detect_heading` (change both together; rules in `docs/素材流程.md` §2 分章), headings without body not counted, volume headings only count when ≥200 chars sit under them; bumping `FileService.CHAPTER_RULES_MARK` (marker line in `data/.defaults-applied`) recounts every txt / md at startup; 0 = no chapters found, -1 = unreadable, NULL = not counted / docx·pdf) is set on save; old rows are backfilled in a background thread at startup (`FileService.backfillChapterCounts`, column added by `SchemaMigrations`). 文件管理 shows it under each card (「N 章」) together with an 「已提取」 badge (extract tasks matched by `bookOf(fileName)`, display only — re-extraction is allowed).

### Rules

- All SFCs use **`<script setup>`** (Composition API); UI text is Chinese, identifiers/comments may be Chinese or English.
- `@` alias → `src/` (configured in `vite.config.js`).
- Keep HTTP calls inside `src/api/*.js` using the shared Axios instances: `request` (Java) and `aiRequest` (Python, `VITE_AI_BASE_URL`, fallback `http://localhost:8021`, 180s timeout — only for `/api/local/**`) (`src/api/request.js`; Java `baseURL` from `VITE_API_BASE_URL`, fallback `http://localhost:8022`, 60s timeout). Views must not create their own Axios instances.
- API helpers unwrap `res.data`; callers treat `response.code === 0` as success.
- Routes are lazy-loaded (`() => import(...)`) with `meta.title` / `meta.icon` consumed by the sidebar; register new pages in `src/router/index.js`. A menu entry with `meta.children: [{path, title, icon}]` renders as an `el-sub-menu` (`layout/Sidebar.vue`); the parent route only redirects (e.g. 小说抓取 → `/novel/crawl/config`).
- Element Plus and all its icons are registered globally in `main.js`.
- Layout: `.app-wrapper` is fixed to one screen (`height: 100vh; overflow: hidden`); only `.app-main` scrolls, so the sidebar stays put. Scroll-to-top must target `.app-main`, not `window`. **Route pages need exactly one root element — no HTML comment before or beside it**: `AppMain` wraps them in `<transition mode="out-in">`, and in dev a top-level comment makes a fragment root, so leaving that page leaves the next one blank (happened 2026-11-02 when exiting the 书房).

- **AI 填写** (when the workspace passes `novel-id` + `ai`): since 2026-11-01 the two buttons below are one `AiRegenButton` (see «Field AI = four ways»; 参考已有 = the old 润色, no 参考 = the old 生成 with an explicit 方向). Number / slider fields are generation parameters and never AI-filled. Shared settings in the header popover `AiFillSettings.vue` (model: 大模型 / 本地 + adapter, 补充要求 with 「AI 给几个方向」, materials picked or AI-matched, blocked source books). Requests go to Java `/api/novel/gen/{id}/ideas` with `kind: fill` and `fill {mode: field|items|category|option, path, fields (schema + option labels), current (filled siblings), itemLabel, count, existing}` plus the editor's **unsaved** `spec`. `novel-options/aiFill.js#applyValue` writes results back (choice labels → option values; unknown labels become custom options via `addOption`). Concurrency (`aiRunning` key → scope path, `ai.loading(key)` / `ai.locked(scope)`): **local model = one request at a time** (one model on the GPU, generation serialised); **API model = parallel**, only buttons whose scope overlaps a running one are locked (`aiFill.scopesOverlap`: one path is a prefix of the other — e.g. 「AI 补全」 on a character card locks that card's fields and 补全本分类 of 角色, not other cards; new-item generation uses `[...group, NEW_ITEMS]` so it doesn't block existing items). Overwriting a filled choice / tags field asks first; text writes show a notification with 「撤销」.
- **Output**: `buildSpec()` → `[{key,label,type,value,display,children}]` (`type: 'option'` for sub-option containers, `'groupItem'` + `name` for group entries) is what the workspace saves as `settings.spec` and the backend turns into constraints; `getConfig()` (`{categories, values}`) is saved as `settings.config` to restore the editor.

## 6. Python AI Service (`python-service/`)

This service is the **AI/ML layer**; the Spring Boot service remains the system of record for files and metadata.

Responsibilities:
1. **Content extraction** — parse uploaded novel/manuscript files (txt/md/docx/pdf…) into clean plain text and structured chapters.
2. **Content analysis** — e.g. chapter segmentation, characters, plotlines, style statistics; results returned as JSON.
3. **LLM fine-tuning** — dataset preparation and **QLoRA fine-tuning with Hugging Face** (`transformers` + `peft`) against remote GPU/LLM resources; manage training jobs and LoRA adapters.

### Novel extraction (implemented)

- `POST /api/models/verify` `{baseUrl, apiKey, model, protocol?}` → `{ok, latencyMs, message, reply}`; `POST /api/models/list` `{baseUrl, apiKey, protocol}` → `{ok, models, message}`.

- **Local extraction** (`app/local_extract.py`, `LocalSession`): base model loaded via `inference.load(..., from_generation=True)` (not reloaded when already resident; an attached adapter is disabled per call), chunks run strictly serially through `inference.chat_generate` (temp 0.2, ≤900 tokens, +400 with materials), same prompt as the API (`llm_client.build_chunk_prompt`); output parsed leniently (`parse_lenient`: code fences, trailing commas, per-field regex salvage), an unparseable chunk is skipped. Refused while training holds the GPU or a chapter job runs; while it runs, `inference.extract_busy()` makes chapter generation / polish, local AI 构思, model load / unload and training (via `unload`) wait or refuse.
- `app/llm_client.py`: OpenAI-compatible `POST {baseUrl}/chat/completions` with `Bearer` key. Friendly errors (401/403 key, 402 balance, 404 model/URL are *fatal* and abort the job; 429/5xx/timeouts retry ×2). Falls back without `response_format` if a provider rejects JSON mode. Local hosts skip the system proxy; remote hosts use it.
- Jobs are in-memory and run one at a time; Java is responsible for persisting results.
- Languages: Chinese (primary) and English novels. Analysis text is always output in Simplified Chinese; character/place names keep the original spelling.
- All `httpx` calls to local services use `trust_env=False` — a system proxy (Clash etc.) otherwise turns `localhost` requests into 502.
- **Material steps ① / ②** (`app/material_facts.py`). **① `scan`** (extraction with `materials.enabled`; optional chapter range `materials.fromChapter / toChapter` (1-based, 0 = to the end; result `range {from, to, total, chars}`, `chapters` / `chapterCards` hold only that range, `ci` counted from its start; golden chapters = the book's first 3); `app/chapter_scan.py`, since 2026-11-02 — design `docs/素材提取改造方案.md` §3.0 / §3.0.2): **one call per chapter, strictly in chapter order** (no merging of short chapters; API concurrency is not used for reading). Chapters longer than the limit (API 20000 chars, GGUF `chunkChars × 2`, in-app local `chunkChars`) are split at paragraph boundaries, read in order and merged into one chapter card. Each prompt carries a **rolling context** chosen in code: the previous 2 one-liners, known entities whose name / alias occurs in the chapter (≤15, only new facts asked), the lead + current state, open threads `T<n>` (≤20; plant ids assigned in code, advance / payoff must cite an id). One call returns entities + facts and the **chapter card**, by `materials.depth`: `fast` (oneLine, events), `standard` (default: + hooks pos × 7 types × strength, payoffs 11 types × strength × amplified × setup, threads plant/advance/payoff, function, emotion, lead / leadChanges, relations, entityMoves, lines ≤3; first 3 chapters + `golden`), `deep` (+ `nodes`, paragraphs numbered `[n]`, ranges fixed in code). Quotes are checked in code (`Source.locate`: normalised substring or ≥60 % char-trigram overlap; ≥4 chars): unverified facts go to the entity's `unverified` (≤10), unverified card items keep the item with `quote: ""`, `verified: false`; lines must match exactly or are dropped; every verified quote stores `at` = offset in the chapter text. A failed chapter is recorded and skipped, retried once after the book, 5 failures in a row stop the job (INTERRUPTED). `rounds: 2` (default now 1) re-reads in order with all known entities, entities only (`pass2`). Aggregation in code (`Book`): category + `_norm_title` of name / aliases, facts deduped by char-bigram overlap. Result: chapters (summary = oneLine + first 3 events, events from the card), `entities [{key, category, name, aliases, facts[{fact, quote, chapter (title), ci (chapter index), at}], unverified[]}]`, `chapterCards[ci]` (status done / failed / empty, card fields, `stats` {chars, paragraphs, avgParagraph, dialogRatio, appear, newEntities}), `threads`, `lead`, `pacing` (`app/breakdown.py`), `preface`, `splitWarnings` (most facts first; the user may delete entities in 实体档案), `factStats {rounds, chunks, failedChunks, factsVerified, factsUnverified, entities}`, `usage`. **② `compile_cards`** (`extractor.compile_job`, input = entities + chapter summaries, `_internal` maps facts back to chapter indexes by `ci` or title): ≥2 facts one call each, 1-fact entities 5 per call → `{useful, title, subtype, summary, detail (100–300), attributes (category template), usage → 作者用法, borrowTip → 借用提示, tags}` (prompt: only the given facts, no invented causes, omit unsupported attributes; values like 「无 / 未提及 / 无明确信息」 are dropped by `_EMPTY_VALUE`); `useful: false` is skipped (`notUseful`). World cards sharing a subtype (≥3) get an extra **体系卡** (subtype 体系, `parts`). **Plot arcs** (`plot: true`): chapter summaries (consecutive identical ones = one block, listed once), 20-chapter windows overlapping 3 → `{title, start, end, function, cause, conflict, turn, result, borrowTip}` with roles abstracted (no proper names), deduped by title / >50 % range overlap. Candidates: `candidateId = sha1(entity key)`, `detail`, `facts[{fact, quote, chapter}]`, `aliases`; saving a candidate copies `detail` and puts `facts` into `material.source.facts` (`components/material/FactList.vue`). Compile stats `{entities, cards, notUseful, systems, arcs, failedCards}`. Model calls go through one `call(messages, max_tokens)` (API / GGUF via `llm_client.chat`, in-app local via `LocalSession.chat`); truncated JSON is repaired back to the last complete object (`_close_truncated`). **Checkpoints** (`app/extract_checkpoint.py`): `data/extract-cache/<key>/meta.json` (fingerprint — scan: file, chars, chapters, jobs, `mode: serial-v1`, `cardsV`, depth, max chars, rounds, categories, focus; `pass1` = one row per chapter / part keyed `ci` or `ci:part`, replayed in order on resume; compile: hash of entity keys + fact counts, plot, chapter count; a mismatch wipes it) + `pass1|pass2|cards|systems|arcs|chunks.jsonl` (one fsynced line per block / card batch / window; torn lines skipped). Measured with GGUF Qwen3-4B Q4 on the RTX 4060 Laptop (《耐瑟瑞尔》 ch. 1–6, 13.6k chars): ≈ 16 s / 1000 chars per reading round and ≈ 18 s per card (2 rounds found 27 entities vs 12 with 1 round, 119 verified / 13 dropped facts) — a 3-million-char novel takes ~14 h per round, so pause / resume matters; compiling cards with a 大模型 is ~1 元 per book. **Eval**: `.venv/Scripts/python scripts/extract_eval.py --text x.txt --chapters 1-10 --run g1=http://127.0.0.1:8002/v1,1 --run g2=…,2 [--run ds=https://api.deepseek.com,1,deepseek-chat,DEEPSEEK_API_KEY] [--baseline ds]` runs scan + compile per group and compares time (reading / total), tokens, verified / dropped facts, cards and entity recall against a baseline, printing the top entities' cards side by side.
- `POST /api/materials/profile {items ≤20, model | gguf: true}` → `{ok, tiers: {id: {tier, reason}}, skipped, usage}` (`app/material_profile.py`, 量级 1–5 by 影响范围; compile cards also output `tier` and code-computed `bookPos`).

Run the 8012 instance on a **copy** of `data/` (`DATA_DIR`) — a Java start marks running tasks INTERRUPTED. Findings (2026-10-29, 15052 materials, need-style queries): vector only Hit@1 59 %, BM25 76 %, RRF 69 %, RRF + rerank top 30 **84 %** (nDCG@5 0.853); reranking 60 / 100 is worse (recall ceiling already 97 % at 30) → keep `RERANK_TOP` 30. **MMR was removed**: at diversity 0.3 it changed 6 % of 灵感墙 results with no diversity gain, because only ~2.5 items per need pass `RERANK_MIN_SCORE` (65 % of reranked top-30 scores < 0.1) and bge-small candidate cosines sit at 0.53–0.64. Don't reintroduce similarity-based diversity without re-running the eval; open question = whether rerank 0.1–0.3 items are usable (threshold 30 may be strict). Details: `docs/素材检索.md` §7–8.
- **Merge** (`app/material_merge.py`): `POST /api/materials/merge/groups {modelId?, items[{id, category, title, text}], threshold (0.82), maxGroup (6)}` — per category, pair score = content cosine, or max(content, (content + title cosine) / 2) when the titles' vectors are ≥ 0.85 alike (two books' 「狼人」 differ in content, not in name), +0.08 when normalised titles are equal / contain each other; pairs ≥ threshold are merged greedily (best first, group ≤ maxGroup, every new member ≥ threshold − 0.08 to all members, so chains don't snowball) → `{groups[{ids, score, minScore}], total, model, ms}` (≤500). Measured on a toy set with bge-small-zh: two differently written 「狼人」 = content 0.72 → score 0.94; 「狼人族」 joins at 0.80; 「吸血鬼」 stays out. `POST /api/materials/merge/draft {category, members[{id, book, title, subtype, summary, attributes, detail}], model | gguf}` — one JSON call: `same` (which members are the same thing), master `title / subtype / summary / detail / attributes / tags`, `variants {id: 这本书独有的具体设定}`; the draft keeps every member as a **可选版本** (`variants {n: {label ≤8 chars, note ≤80 chars}}`, same-name-different-thing allowed) and puts only the commonality on the master. **Grounding** (char bigrams, `_grounded`, 40 %): master attribute values and detail sentences must be supported by **at least two members' own texts** (else dropped → `droppedAttributes`; a one-member detail is that version's, and would otherwise leak into 「只用另一版」); a version's `note` must be supported by that member (else emptied) and its `label` share a bigram with it — the 4B GGUF otherwise pads the master with invented 外形 / 能力 / 与人类的关系.

### Web novel crawler (`app/crawler/`, `/api/crawl/**`, called by Java)

- `POST /api/crawl/preview` (book), `POST /api/crawl/jobs`, `GET /jobs/{id}`, `POST /jobs/{id}/cancel`, `GET /jobs/{id}/text` (UTF-8 txt), `POST /jobs/{id}/release`, `GET /presets`; responses `{code, message, data}`. Jobs are in memory; different sites run in parallel (≤ `MAX_PARALLEL_SITES` 6), the same site (`scheme://netloc`) one at a time via a per-site lock (`_run_in_lane`, cancellable while waiting); ≤8 unreleased texts kept.
- **Catalog** (`catalog.py`, bounded — never the whole site): `POST /api/crawl/catalog/jobs` (`CatalogRequest`: `homeUrl`, `rule`, `sampleUrl`, `categories`, `knownUrls`, `phase`, `maxBooks` ≤500, `maxCategories`, `maxListPages`, `contentSamples`, `tocPages`, `tocAsync`, `tocTargets[{bookUrl, tocUrl, bookName}]` (phase `toc`), `catalogDir` = `site-catalog/<name>`), `GET /catalog/jobs/{id}?since=N&tocSince=M` (books after N, `booksTotal`, `tocUpdates` after M `{bookUrl, tocUrl, chapterCount, firstChapter, latestChapter, tocPages, tocPath, tocOk, error}`, `tocUpdatesTotal`, `report`; `_fill_tocs` falls back to the book page as TOC, one failed book doesn't stop it, 5 consecutive network failures do), `POST /catalog/jobs/{id}/cancel`; sync AI endpoints `POST /catalog/plot-tags`, `/catalog/intro-match`, `/catalog/tag` (model passed by Java). Books are recognised by the learned sample's URL pattern, else `bookLinks` / heuristics (retried with heuristics when the pattern finds nothing). **Name / author / category always come from the book's own page** (`parser._detail_book_name` / `_detail_author` / `_detail_category`, also used for TOC pages): `og:novel:book_name|author|category` first; otherwise name candidates (rule XPath, every h1/h2) must match the first segment of `<title>` (「书名最新章节_书名全文阅读_站名」, site name excluded), author = 「作者：」 in the title's block or the text right after it (never an earlier header / sidebar one), category = breadcrumb (`path|bread|crumb|location` class or 「当前位置」 text with `>` separators; nav bars ignored) → 「类别 / 分类：」 near the title (「玄幻小说」→「玄幻」); the list-page link text and the list category are only fallbacks (sidebars list other genres' books). A book page redirected away (home / other host / book id gone, `_redirected_away`) is an error. Book names are cleaned of SEO tails (`parser.clean_book_name`: 「…小说全文阅读顶点」「…最新章节无弹窗免费阅读」「…txt下载」; only compound tails with 阅读 / 下载 / 最新章节 / 无弹窗). Some sites put the real title in the author field — that is shown as the page states. Detail page wins over the TOC page (its `<title>` often has a「目录」suffix); `<meta name=description>` ranks after the page's intro block (it is often site-wide). 5 consecutive network failures or a TOC write error stop the job; collected books are still returned with a report.
- `fetcher.py`: anti-bot pages raise `BlockedError` with a plain reason (Cloudflare challenge = 403/429/503 + `server: cloudflare` or「Just a moment」markers; script-jump token pages = tiny 200 page with only a `location=` script and no links) — the crawler never executes or solves them; AI 解析 stops at once (no model calls). http/https only, **public addresses only** (loopback/private rejected unless `CRAWL_ALLOW_PRIVATE=1`, for local fixture tests; domains resolving into `198.18.0.0/15` are allowed — Clash fake-ip/TUN mode), non-ASCII URLs percent-encoded, robots.txt respected by default, min delay 300 ms (default 1000), retries on 5xx/network, encoding from header/meta (gbk → gb18030) else `text_loader.decode_text`. Env `CRAWL_USER_AGENT`.
- `parser.py` heuristics: chapter links = links matching `第X章/Chapter N/1.` in the container holding most of them, deduped keeping the **last** occurrence (drops the "最新章节" block); content = block with most direct text (id/class like content ×1.5); `下一页` pagination for TOC and in-chapter (`123.html → 123_2.html` only); default ad-line filters apply to lines ≤ 80 chars. Site heuristics: categories (`_guess_categories`) = groups of ≥3 short same-host links in one container, **book-pattern links excluded** (`parse_site(..., book_re)`), scored by size + 3 × category-word hits (`CATEGORY_WORDS`: 玄幻 / 武侠 / 都市 / 言情 / 历史 / 科幻 / 女频 …) × 2 when ≥60 % share a non-numeric first path segment (e.g. `/class/`) — previously the largest group won and a home-page book list was taken for the categories; book links = largest group of non-chapter links on a list page (falls back to all candidates when the page only has 1–2 books), TOC link = link text matching 开始阅读/全部章节/目录, and the detail page doubles as TOC when it already contains chapter links.
- Failed chapters get a placeholder and the job continues; 10 consecutive failures or > 50 % failed → job fails. Output txt keeps chapter titles so `text_loader.split_chapters` works.
- **Resume** (`checkpoint.py`, `CrawlRequest.resumeKey` / `newOrigin`): `meta.json` stores the chosen chapter list (so a dead TOC page does not block resuming), `chapters.jsonl` one fsynced line per fetched chapter (a torn last line is skipped; failed chapters are not stored and are retried). Network-type errors (`fetcher.NetworkError`: DNS failure, timeouts, 5xx after retries) do not count as chapter failures: the job waits `NETWORK_WAITS` (≈ 5 min, cancellable) and retries the same chapter, then fails with the checkpoint kept. `GET /api/crawl/checkpoints/{key}`, `POST /api/crawl/checkpoints/{key}/delete`.
- **Resume self-test** (no network): `.venv/Scripts/python scripts/crawl_resume_selftest.py` — cancel mid-book, restart the fake site on another port, resume with `newOrigin`, assert only missing chapters are fetched and the TOC is not.
- **Self-test** (no network): `.venv/Scripts/python scripts/crawl_site_selftest.py` builds a fake book site in a temp dir, serves it on 127.0.0.1, then asserts the AI-parse site exploration's 站内搜索 probe (GET form with a hidden field → results contain the book; a login-only form is not taken for search), a catalog test (3 categories, 分类翻页, TOC / intro / tags / content samples, TOC files, verdict `usable`), a `scan` that only adds new books, and a full single-book crawl. `.venv/Scripts/python scripts/crawl_fixture_server.py [port]` (default 8899) keeps that fake site up so the crawl page can be exercised end to end — start the AI service with `CRAWL_ALLOW_PRIVATE=1` and AI-parse `http://127.0.0.1:8899/book/jw/`, confirm, then 全自动抓取.

The final chat-template count is verified and pieces are rolled back (extended L3 → older summaries → next preview → ledger → cards → arc → latest summary → L3) until it fits. Report layer `L1b_facts`, `included/dropped.facts|nextPreview`. API models estimate CJK at 1.0 token/char.
- **Writing flow** (`novel.params`, switches in the 写作 form 「写作流程」): `planChapter` (default on) = one JSON call before writing → `chapter.plan {beats[3–6], foreshadow[], hook}` (core + ledger + previous summary + goal + next outline chapter; failure → `planError`, writes from the goal); each segment's task lists the beats and 「本段主要写第 k 个节拍」 (`prompts.beat_at` = written / target share; last segment gets the hook). `extractFacts` (default on) = the summary call becomes `_digest` (JSON `{summary, foreshadow, characters (+ goal / obstacle / relations / knows when the chapter makes them clear), timeline, clocks}`, ≤1300 tokens, the open-foreshadow list is sent so the model cites ids) → `facts.merge` + `chapter.facts` (this chapter's changes); unparsable JSON (small local models) → `factsError` + the old plain summary call, the chapter still completes. `reviewChapter` (`null` = on for 大模型, off for local) = one JSON call after the digest comparing core settings, `view_before(n)` ledger, recent summaries and the text → `chapter.review {issues[{type setting\|character\|timeline\|foreshadow\|logic, quote, found (quote occurs verbatim → UI can jump to it), detail, fix}], at, model, ignored}` / `{error}`; reports only, never edits. All three are `_json_call`s (adapter off, `GenParams.json_mode` → `response_format` for API models, lenient `_parse_json`), recorded as call types `plan` / `digest` / `review`. A hand edit of the text sets `factsStale` (UI offers 重新提取). `list_chapters` exposes `reviewIssues` (null = not checked / failed / ignored)
- **Segmented chapters** (`chapter.py`): each segment ≤ `params.segmentTokens` (768, capped at window/4) and only sees the chapter tail, never the whole chapter. Stops at ~95% of target chars, natural end on the last segment, cancel, or a segment cap. Then a summary call (≤150字, temp 0.3); when > 8 unmerged chapter summaries exist the oldest 5 are merged into `arcSummary`. Every call (type, prompt/completion tokens, finish reason, seconds, layer report) is stored on the chapter and added to the workspace totals. One generation job at a time; refused during training; model load/unload/training are refused while a chapter is generating.
- **Storage** (`store.py`): `data/novels/<id>/novel.json` (incl. `outline`) + `facts.json` (故事账本) + `chapters/NNNN.json` (`${DATA_DIR}/novels`; `NOVELS_DIR` still overrides). Python is the only writer; Java may read per `data/README.md`. All persistence goes through `store.py` so the planned MySQL migration replaces only that module.

### Conventions

- FastAPI app served by Uvicorn on **port 8021** (test 8011), all routes prefixed with `/api`, Pydantic v2 models for request/response.
- Do **not** re-implement file storage or a second file database. Consume files via the Java backend (by file id / relative storage path) or a shared volume, and return extracted/analyzed results over HTTP.
- Fine-tuning is long-running: run training as **background/async jobs with a status endpoint** (queued/running/succeeded/failed + logs), never block a request worker.
- Keep model weights, datasets, and LoRA adapters out of Git: `python-service/models/` is git-ignored; large base models are registered by path instead of copied.
- Add `requirements.txt` (or `pyproject.toml`) and document the Python version and CUDA/torch assumptions.

## 7. Local Development (Windows)

- Prerequisites: **JDK 17** (the project does not compile on JDK 8), Maven, Node.js. **No database server is needed** (SQLite file `data/nan_novel.db` is created on first start). The pre-migration MySQL schema `test10000` is kept untouched as a rollback source only.
- `start.bat` launches the services with one click. It contains **machine-specific hardcoded tool paths** (`JAVA17_HOME`, `MAVEN_BIN`, `NODE_DIR` under `D:\workplace\...`) — edit them to match the current machine; do not "fix" them for everyone.
- `start.bat` also starts the AI service with the interpreter saved on the **Python 环境** page (`python-service/.python-env`), else `python-service/.venv`. To use a local GGUF model, start it on the **llama.cpp** page (`/ai/llama`, see the `/api/local/llama` row) and pick the 「GGUF」 model source; manual alternative: **`start-llama.bat`** (llama.cpp `llama-server` on `127.0.0.1:8001`, in its own console window — closing it stops the server; double-click = default model, drag a `.gguf` onto it = that model, `start-llama.bat [gguf] [ctx]`; machine-specific `LLAMA_DIR` / `DEFAULT_MODEL` at the top, falls back to the old Qwen2.5-7B GGUF; when 8001 is already listening it says so and closes after 5 s; keeps `--parallel 1 --cache-ram 0`, the defaults crash with a CUDA error after ~15 min on the RTX 4060 Laptop) and add a config with base URL `http://127.0.0.1:8001/v1`, concurrency 1. The project never starts / stops llama.cpp itself — it is just an OpenAI-compatible endpoint to `llm_client.py`. `start.bat` can run it as a 4th window (`START_LLAMA` at its top, **default 0**) — normally start GGUF models from the 「llama.cpp」 page instead (same port, only one of the two at a time).
- **Model comparison report** (DeepSeek vs local GGUF vs safetensors: extraction / chapter / AI fill, speed + quality, test method): `模型对比测试报告.md` in the repo root.

## 8. Rules for Code-Generating Agents

- Preserve existing patterns: `Result<T>` + `BizException` on the backend, `src/api` Axios modules on the frontend.
- Prefer extending the current file-management framework over introducing parallel mechanisms (new storage layouts, new response wrappers, new HTTP clients).
- Any new frontend↔backend contract must be updated in **three** places: controller, `src/api/*.js`, and this document if endpoints/conventions change.
- Never commit secrets, uploaded user files, model weights, or datasets; keep `data/` (except `README.md`/`.gitkeep`), `picture/`, `docker.zip` and Python artifacts out of version control.

## 9. Cross-world persona cards (跨世界观角色卡) & 试聊

Design details, parameters and measurements: [`docs/跨世界观角色卡.md`](docs/跨世界观角色卡.md), [`docs/试聊.md`](docs/试聊.md) (update them with any change to extraction / adaptation / checks / identity test / chat).

- **Flow**: 原型卡 (prototype: traits `{layer, kind core|adaptable, locked, provenance quoted|inferred|user, confidence, evidence}`, rules over 6 situations, expertise + `worldBound`, voice + verified lines, arc, signature, memories, `uncertain`, 20 % `holdout` for the judge) → append-only versions → 适配版本 (adaptation into a workspace's settings or a hand-written world) → confirm → 用于工作区 (snapshot into Python `novel.personas`) → writing / review / 试聊; 辨识度测试 per adaptation.
- **Provenance is decided in code**, never by the model or the frontend: Python `persona.build_prototype` (quotes verified with `material_facts.Source.locate`, unverified dropped); Java `PersonaService.saveVersion` compares with the previous version (changed → `user` + `aiText`, unchanged → previous provenance/evidence, new → `user`). Core / locked trait texts are copied by code into adaptations; `check_adaptation` → `{missingManifest, changedLocked, leaks, missingSituations, ok}`; `render_brief` builds the 【人物内核·名字】 block.
- **Python** (`app/persona.py`, routes in `main.py`): `POST /api/persona/jobs {kind: extract|test, name, aliases, whole, text, files[{id, ext}], seedFacts, maxBlocks (60), chunkChars (3000), prototype, adaptation, judgeModel?, model|local|gguf, resumeKey p<cardId>}` (same single-worker queue / job endpoints as extraction; checkpoint stages `notes` / `synth`), `POST /api/persona/adapt {prototype, world?, novelId?, wish, model|local|gguf}` → `{adaptation, usage}`, `POST /api/persona/adaptation/check {prototype, adaptation}` (no model), `POST /api/persona/chat {character, persona?, novelId?, world?, mode free|scene|interview, scene, inner, messages, summary, boost, model|local|gguf}` → `{reply, inner, summary?, summarizedUpTo?, drift?, usage}`; `GET|POST /api/gen/novels/{id}/personas` (snapshot list, whole replace).
- **Generation hooks**: `spec.build_for(novel, spec?)` = `build` + `apply_personas` (role containing 主角 → core, others → cards `persona.<name>` keyed by name + aliases, ranked before normal cards in `context.build`); `_plan` / `_review` get `personas` = rules of the persons mentioned (`prompts.plan_user/review_user(..., personas)`), review type `persona` (人物内核不符) + code scan `persona.scan_unknowns` (person present + an `unknowns` term in the text); `ideas._context` uses `build_for`.
- **Java** (`PersonaService`, `PersonaController`, `/api/persona/**`, single background thread `persona`, polls `/api/extract/jobs/{id}` every 3 s): cards `GET /cards?keyword=&tag=` · `GET /cards/{id}` (current version as `content`) · `POST /cards/extract {name, aliases?, kind?, tags?, source{type: text|file|extract, text?, fileIds?, extractId?, entityKey?, whole?}, maxBlocks?, chunkChars?, model}` · `POST /cards/create` (blank) · `/cards/{id}/resume|stop|meta|delete`; versions `GET /cards/{id}/versions[/{no}]` · `POST /cards/{id}/versions/save {content, note}` · `POST /cards/{id}/versions/{no}/restore`; adaptations `GET /cards/{id}/adaptations` · `POST /cards/{id}/adapt {version?, novelId?, world?, wish?, model}` (requires `content.coreConfirmed`) · `GET /adaptations/{id}` · `POST /adaptations/{id}/save {content}` (re-check, back to DRAFT) · `/confirm` · `/delete` · `/apply {novelId?, role?}` (CONFIRMED only) · `/test {model, judgeConfigId?}` · `/test/cancel`; workspace `GET /novels/{novelId}` (`outdated` vs the adaptation) · `POST /novels/{novelId}/remove {name}`; chat `GET /chats?cardId=&adaptationId=&novelId=&name=` · `POST /chats/start {cardId?|adaptationId?|novelId + character{name, card, greeting?, userRole?}, mode?, scene?, inner?}` · `GET /chats/{id}` · `/chats/{id}/update|send {message, model, boost?}|regenerate|feedback {index, rating good|bad|null, reason?}|delete` · `GET /feedback?cardId=&adaptationId=`.
