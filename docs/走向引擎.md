# 走向引擎：精彩又合理的后续走向

> 相关代码：Python `app/generation/directions.py`，经 `ideas.generate` 的 `kind: story_direction`（整理局面 = `kind: situation`）；
> Java `NovelGenService.ideas`（同一个 `/api/novel/gen/{id}/ideas`）；前端 `components/novel/IdeaPanel.vue`「AI 构思后续走向」。
> 评测：`python-service/scripts/direction_eval.py`。输入的局面见 [世界书](世界书.md)。

## 1. 流程

```
① 局面     worldbook.snapshot（人物想要什么 / 阻碍 / 关系 / 秘密、未回收伏笔、定时事件、阶段、大纲接下来、前情、设定）
           账本里还没有人物目标时先「整理局面」一次（存进账本，以后不用再整理）
② 发散     一次调用，按驱动各出 2 个候选（temperature 0.95）：
             欲望碰撞 · 伏笔回收 · 信息差引爆 · 素材注入（只在选了素材时）· 反转
③ 审稿     一次调用（temperature 0.2）逐条：合理 1–5、硬伤、精彩 1–5；有硬伤但点子值得留 → 给修正版（冲突保留甚至加强）
           代码再查：引用了不存在 / 已回收的伏笔编号、尚未登场的设定被正面写出 → 合理压到 ≤2
④ 排序     合格 = 修正过的或合理 ≥3；按 合理 + 1.3 × 精彩 排（修正过的合理按 4 算），每种驱动最多 2 条；合格的不够才用不合格的补
⑤ 作者     支持 / 追加 / 拒绝（和以前一样），选中的作为 chosenDirections 用于书名 / 大纲 / 章节题目
```

卡片上显示驱动类型、审稿分数、用到的伏笔 / 人物；修正过的标「已按审稿修正」（悬停看修正前），没修正但有问题的标黄。
**本地小模型**：③ 跳过（JSON 太长容易坏），按 ② 的顺序、去掉代码查出问题的。

和旧「后续走向」（`kind: direction`）相比：上下文从「勾选的设定 + 最近 10 章摘要」换成整个世界书（不受 IdeaPanel 的设定 / 章节勾选影响）；
旧 kind 保留给设定页「AI 给几个方向」（生成补充要求，另一件事）。

## 2. 评测方法（`direction_eval.py`）

- **样本**：已有的小说提取结果（每章摘要 / 人物 / 事件 / 伏笔），截到第 K 章做成测试工作区——章节 = 摘要，人物 = 设定里的角色卡
  （出场最多的为主角），伏笔 / 事件 = 账本，K − 8 章之前合成前情概要（模拟 `_merge_arc`）。7 个样本：4 本书（悬疑科幻、西游同人、
  穿越领主、恐怖），K = 30 / 40 / 60 / 90 / 100。原作第 K+1 ~ K+5 章摘要 = 真实后续（只给裁判）。
- **裁判**：DeepSeek，看的是完整前情（与被测系统的上下文无关）。逐条：合理 1–5 + 矛盾、精彩 1–5 + 分项、是否用到伏笔、是否空泛；
  另一调用对照原作后续打 接近 0–2；同一样本同一次运行的两组走向整组比较（A / B 位置随机）。
- 每样本跑 2 次 × 5 条 = 70 条走向 / 14 组比较。

## 3. 结果（2026-10-30，DeepSeek）

| | 旧（后续走向） | v1 | v2 | **v3（采用）** |
|---|---|---|---|---|
| 合理 | 2.99 | 3.47 | 3.30 | 3.31 |
| 精彩 | 3.51 | 3.56 | 3.59 | **3.73** |
| 冲突强度 | 3.63 | 3.37 | 3.61 | 3.73 |
| 有矛盾 | 89% | 74% | 86% | 81% |
| 空泛套路 | 29% | 13% | 9% | **7%** |
| 接近原作（0–2） | 0.16 | 0.30 | 0.11 | 0.21 |
| 整组·自洽（新胜 / 14） | — | 13 | 13 | 13 |
| 整组·精彩（新胜 / 14） | — | 5 | 8 | **10** |
| 整组·总体（新胜 / 14） | — | 13 | 12 | 13 |
| 每次 token / 时间 | 1.8k + 0.5k / 5 s | 6.6k + 3.6k / 27 s | — | 6.4k + 3.0k / 24 s |

- **v1**：只强调合理 → 最自洽，但冲突变弱（3.37），整组精彩输 5:9。审稿改写不是原因：改写过的精彩 3.61 > 没改写的 3.36。
- **v2**：发散加「不要保守：合理不等于平淡」、审稿修正「冲突保留甚至加强」、排序 精彩 × 1.3、**强制每种驱动各 1 条** →
  精彩赢了，但合理掉回 3.30：强制多样性把最弱的驱动顶进前 5——按驱动拆开，信息差 / 素材注入 合理 3.07、93% 有矛盾
  （评测没给素材，「素材注入」只能凭空引入新因素），反转最精彩（3.93），欲望碰撞 / 伏笔回收最稳。
- **v3**：保留 v2 的提示词和权重，**没选素材时不出素材注入**，不强制每种驱动各 1 条（每种最多 2 条）→ 精彩最高、整组 13 / 10 / 13。

**局限**：裁判和被测系统都是 DeepSeek（可能偏好同一模型的写法），样本的章节是摘要而不是正文，14 组比较的波动不小
（同一设置重跑几个百分点的变化是正常的）；「有矛盾」的比例很高是因为裁判很严，适合横向比较，不代表绝对质量。
「接近原作」只是参考：原作的写法不是唯一正确的后续。

## 4. 成本

一次出走向 = 2 次调用（发散 + 审稿），约 6–7k 输入 + 3k 输出 token、20–30 秒；第一次还要加一次「整理局面」（约 4k + 1k）。
DeepSeek 下每次几分钱。旧流程是 1 次调用、约 2k token、5 秒。
