## Java: extraction tasks

### Novel extraction API (`NovelExtractController`)

| Method & path | Purpose |
|---------------|---------|
| `POST /api/novel/extract/{fileId} {materials?, model?}` | Create an async extraction task for a txt/md/docx/pdf file; returns the task (`QUEUED`). `model` = `{source: api, configId?}` (any **VERIFIED** config, used for this task only — the active config is not changed; empty = active) or `{source: local, baseId, chunkChars?}` (in-app 本地模型, no tokens; `chunkChars` 1000–6000, default 2500) |
| `POST /api/novel/extract/{id}/extend {toChapter}` · `POST /{id}/reread {cis}` | **接着读到第 N 章** (0 = to the end) / **重读这几章** (`cis` = indexes within the range, 1–200) on SUCCEEDED / INTERRUPTED extractions that recorded entities **and still have their checkpoint** (since 2026-11-03 serial-scan checkpoints are kept after success; older successes lost theirs → 400 「这次提取没有保留断点…」): `restartFromCheckpoint` patches `options.materials` (`toChapter`, or `reread {id, cis}`), clears `job_id` (else `adopt` would re-save the old Python job) and the result path / size / sha (else `live` says finished), marks INTERRUPTED and calls `resume`. Python replays the checkpoint (fingerprint excludes `toChapter` / `reread`): extend reads only the new chapters; reread re-reads rows of `cis` whose `rr` ≠ the reread id (stamped on the new rows) and numbers new threads after the book's highest `T<n>`. The result is regenerated from all rows (previous write-backs are replaced). UI: workspace header 「继续提取…」 (estimate via `components/material/extractEstimate.js`), left column switch 「重新提取」 (tick chapters or 全选 → 重新提取选中) |
| model on resume (2026-11-03) | `resume` (also used by extend / reread) runs `source: api` tasks with the **currently active** model config and rewrites `options.model.configId` (the checkpoint does not depend on which API config is used); `ExtractOptionsForm` / `CompileDialog` no longer remember the last config id — 大模型 defaults to the active config |
| `POST /api/novel/extract/draft/{fileId}` · `POST /{id}/draft {model?, materials?}` · `POST /{id}/start {materials?, model?}` | **未开始 (DRAFT)** extractions: 「提取」 in 文件管理 / 抓取进度 creates (or reuses the file's existing) DRAFT row and opens the 提取工作区 on it, so leaving before starting keeps it under 提取中 (「未开始」, 工作区 / 删除); `draft` saves the workspace's settings + chapter range into `options` (model whitelisted to source / configId / baseId / chunkChars, ≤20000 chars); `start` = the same as the fileId submit but on that row (conditional update DRAFT → QUEUED, only once; else 400 「这次提取已经开始了」). Java restarts don't touch DRAFT rows |
| `POST /api/novel/extract/{id}/pause` | 暂停 a QUEUED / RUNNING task → Python stops before the next chunk → **INTERRUPTED** 「已暂停」 (checkpoint kept) |
| `POST /api/novel/extract/{id}/cancel` | Cancel a QUEUED / RUNNING / INTERRUPTED task (running → Python stops first) → FAILED「已取消」. Only cancel moves a task to 提取失败 |
| `POST /api/novel/extract/{id}/resume` | **继续** an INTERRUPTED task: if the Python job (`job_id`) is still queued / running / succeeded (Java restarted) it is adopted and polled; otherwise re-submitted with the stored `options` (`{model, materials}`, column `novel_extract.options`, no key) and the same checkpoint key `e<id>` — finished chunks / blocks / cards are not redone |
| `POST /api/novel/extract/delete {ids}` | Delete **FAILED** and **DRAFT** tasks only (others skipped) and their Python checkpoints → `{deleted, skipped}` |
| `GET  /api/novel/extract/list` | Tasks without `result`, `create_time` descending; each has `pendingCount` (PENDING candidates of that task, `MaterialService.pendingCountsByExtract`) |
| `GET  /api/novel/extract/{id}` | Task detail; `result` is the extraction JSON string (chapters, characters, style); unfinished tasks carry `checkpoint` (`{exists, stages, running}` from Python, null when unreachable) and `options` |
| `GET /api/novel/extract/split/{fileId}` · `GET /{id}/live?since=N` · `GET /file/{fileId}/chapters/{index}/text` | 分章预览 (Python `split-preview`, same rules as extraction → `{chars, total, chapters[{index (1-based), title, kind, chars}], warnings}`); **逐章** while extracting → `{status, progress, message, live: {exists, range, chapters? (since=0), rows[{ci, status done\|failed\|partial, card, entities, threadOps, error}], next, current, running, pacing?, threads?, entities?, appear? (when since=0 or new chapters arrived: `chapter_scan._live_breakdown` replays the checkpoint, `mf.Book` re-aggregates pass1 + pass2 entities, and `appear` = names found in the read chapters' text — Java passes the task's fileId / extension so Python can load it)}}` or `{finished: true}` once the result file exists (the UI then builds the same rows from the result); one chapter's text by file + whole-book index (0-based) → `{index, title, kind, text, total}` (works before a task exists) |
| `POST /api/novel/extract/{id}/result {chapters[], characters[], style, …}` | Save a hand-edited result (whole JSON replaced; must contain `chapters`; SUCCEEDED tasks only). Rewrites the file via `ExtractResultStore.write`, updates `result_size` / `result_sha256` / `chapter_count`, adds `editedAt` to the JSON; if the DB update fails the old file is written back |

- Table `novel_extract` (DDL `sql/novel_extract.sql`, auto-created via `spring.sql.init`): `id`, `file_id`, `file_name`, `status` (DRAFT/QUEUED/RUNNING/INTERRUPTED/SUCCEEDED/FAILED), `options` (submit JSON, or the draft settings while DRAFT, added by `SchemaMigrations`), `progress`, `message`, `job_id`, `result_path`, `result_size`, `result_sha256`, `word_count`, `chapter_count`, `candidate_count`, `create_time`, `update_time`. **The full result JSON is not stored in the DB**: `ExtractResultStore` writes `data/extract-results/<id>.json` (temp file → fsync → atomic rename, SHA-256 recorded) before the row is marked SUCCEEDED (write failure → FAILED, no path; DB failure → file removed). `GET /api/novel/extract/{id}` reads it back into the transient `result` field (same API shape); a missing / tampered / out-of-tree file yields `result: null` and an explanation appended to `message`.
- `NovelExtractService` runs tasks on a single background thread using the chosen model (提取工作区 `ExtractOptionsForm` 「提取模型」: 大模型 = a verified config, local hosts tagged 「本机 · 免费」, or 本地模型 + 分段字数 + time estimate; remembered in localStorage `nan_novel.extract.model`; snapshot taken at submit; no config → 400). Python 400 `detail` (e.g. GPU busy) is shown in the task message: submits to Python `POST /api/extract/jobs`, polls `GET /api/extract/jobs/{jobId}` every 3s, and persists progress/result. **Any error while running** (Python unreachable / restarted / job failed / 400 rejection) and tasks left QUEUED/RUNNING at a Java restart become **INTERRUPTED** (stay under 提取中, 继续 or 取消); only tasks without stored `options` (pre-migration) become FAILED, and a result-file write failure is FAILED. Every extraction path checkpoints: chapter-only per chunk (`chunks.jsonl`), entity recording per block (`pass1|pass2.jsonl`, below); Python refuses a second job on a checkpoint key that is still in use. Every submit sends `resumeKey: e<taskId>`; after the result is saved Java deletes the checkpoint (`POST /api/extract/checkpoints/{key}/delete`). A task that recorded entities ends with 「提取完成：N 个实体、M 条事实（丢弃 x 条对不上原文的），可以「整理卡片」」 and creates **no** candidates.
- Python URL: `ai.service.url` in `application.yml` (default `http://localhost:8021`).

## Java: material library

### Material library API (`MaterialController`, `/api/material/**`)

Reusable creative material extracted from novels or added by hand. **Nothing enters `material` without explicit confirmation**: AI output is stored as `material_candidate` (PENDING) and only "保存" turns it into a material.

| Method & path | Purpose |
|---------------|---------|
| `GET  /api/material/categories` · `GET /tags?category=` | Fixed categories with counts; tag cloud `[{tag, count}]` |
| `GET /api/material/list?category=&tags=a,b&tagMode=all\|any&keyword=&sourceBook=&excludeBooks=a,b&pinned=&page=&size=` | Keyword (title/summary/subtype/detail/tags) + tag search, paged (MyBatis-Plus `Page`, needs `MybatisPlusConfig` pagination plugin). `sourceBook` (`__manual__` = no source), `excludeBooks` (pinned items still shown), `pinned=true` |
| `GET /api/material/sources` · `POST /sources/delete {book, withCandidates?}` · `POST /{id}/pin {pinned}` | Source books `[{book, count, pinned, pending}]`; delete a book's **unpinned** materials (optionally ignore its pending candidates) → `{deleted, kept, candidatesIgnored}`; pin = 保留 |
| `POST /api/material/semantic-search {query, category?, tags?, excludeBooks?, limit?}` | AI semantic search with the **active** model config: Python `/api/materials/expand` (query → keywords/tags/categories) → SQL prefilter (whole library if ≤150 items, else LIKE on expansions, cap 150) → Python `/api/materials/rerank` (score 0–100 + reason) |
| `GET /api/material/profile/status` · `POST /profile/start {model: {source: api, configId?} \| {source: gguf}, onlyMissing? (default true)}` · `POST /profile/stop` | **素材量级** (`MaterialProfileService`, background single batch, pausable): `material.profile {tier 1–5 (1 个人 / 街头, 2 地方, 3 一国 / 大宗门, 4 大陆 / 天下, 5 神明 / 世界之外), tierReason, tierBy ai\|user, bookPos 0–1}`; first fills `bookPos` in code (earliest fact chapter ÷ chapter count, from the extraction result), then Python `POST /api/materials/profile` (`app/material_profile.py`, 20 per call, only 1–5 / in-batch indexes kept). `tierBy = user` (changed in `MaterialEditor`; `MaterialService.mergeProfile`: an edit counts only when the tier differs) is never overwritten. New cards get `tier` / `bookPos` from 整理卡片. Status `{total, labeled, missing, byUser, running, batchTotal, done, failed, positions, lastError}`; UI `components/material/ProfilePanel.vue` (素材库 left column) |
| `POST /api/material/vector-search {query, modelId?, category?, tags?, excludeBooks?, limit?, mode?: hybrid\|vector, rerank?, novelId?}` (`novelId` → each result gets `tier` / `fit` against that workspace's story stage, plus `stage`; MaterialPicker `novel-id` skips `far` when prechecking; AI 构思 auto-match drops `far` before retrieval; `StageFit` rules in `docs/素材检索.md`) (merged masters are recalled **per version**: the master's own text plus one text per member — master title + label + note + member text — go into the pool, hits are mapped back to the master, deduped keeping the best version, with `matchedVariant` / `matchedLabel`; `limit × 2` asked from Python; keyword search also returns a master when one of its members matches) · `POST /vector-index {modelId?, encode}` · `POST /vector-feedback {query, modelId, shownIds[], pickedIds[], context}` | **Local retrieval (RAG recall + rerank, no LLM, no tokens)**: same category / tag / blocked-book filters, no keyword prefilter (≤20000 items). Python: dense vectors (`BAAI/bge-small-zh-v1.5`, GPU) + BM25 (`app/local/lexical.py`, jieba; all distinct material tags are sent as `vocab` so 网文 terms like 退婚 / 扮猪吃虎 stay whole) each recall top 50 → reciprocal rank fusion (k=60) → cross-encoder `BAAI/bge-reranker-v2-m3` reranks the top 30 (`app/local/reranker.py`). Default `hybrid` + rerank; no reranker model / OOM → fused order, `reranked: false` + `rerankSkipped`. → `{results[{material, score(0–100), similarity, vecRank, lexRank}], reranked, rerankSkipped, rerankModel, rerankMs, mode, queryTokens, total, considered, model, modelId, device, encoded, cached, ms}`; **score = rerank relevance × 100 when reranked (`MaterialService.RERANK_MIN_SCORE` = 30 ≈ relevant), else cosine × 100 (relative only)**. Text per material = title / subtype / tags / summary / attribute **values** (no category name or attribute keys — they make every vector alike). `vector-index` = count vectorised (`encode:false`) / vectorise all missing; search vectorises missing ones on the fly. Feedback (picked vs shown) goes to `data/material-index/feedback.jsonl` for future fine-tuning |
| `GET /api/material/{id}` · `POST /save` (no id = create, source `manual`) · `POST /{id}/delete` · `POST /use {ids}` | Detail / CRUD / usage counter when applied to a workspace |
| `POST /api/material/merge/find {categories?, books?, crossBookOnly?, threshold?, maxGroup?, modelId?}` · `GET /merge/list?status=open\|APPLIED\|IGNORED&category=&crossBook=&page=&size=` · `GET /merge/counts` | **精炼 / 合并 ①** (`MaterialMergeController` / `MaterialMergeService`, local, no tokens): unmerged materials of the chosen categories (default all but 情节) / books (≤20000) → Python `/api/materials/merge/groups` → suggestions `material_merge` FOUND (old FOUND rows replaced; a member set already DRAFTED / APPLIED / IGNORED is not suggested again; `crossBookOnly` skips same-book groups) → `{considered, found, skipped, groups, model, ms}`. List = open (FOUND / DRAFTING / DRAFTED) cross-book first, then by score, each with `members` |
| `POST /api/material/merge/draft {ids, model: {source: api, configId?} \| {source: gguf}}` · `GET /merge/draft/status` · `POST /merge/draft/stop` | **② AI 合并稿** (optional): one background batch at a time, one Python `/api/materials/merge/draft` call per group, saved immediately (DRAFTED; failure → FOUND + `message`; fatal key / balance errors stop the batch); stop / restart → unfinished rows back to FOUND. Status `{running, total, done, failed, currentId, lastError}` |
| `POST /api/material/merge/{id}/apply {memberIds?, title?, subtype?, summary?, detail?, attributes?, tags?, variants?: {memberId: {label, note}}}` · `POST /merge/ignore {ids}` · `POST /merge/restore {ids}` · `POST /merge/unmerge/{materialId}` | **③ 合并** (user confirms; title / summary default to the draft, then the first member — detail, attributes and subtype only ever hold the **commonality**, never one member's values; ≥2 still-unmerged members): new **master** material, `source = {type: merge, mergeId, members, books, variants[{id, book, title, label (版本名), note (独有设定)}]}` (each member = one 可选版本; labels are appended to the master's tags; old `note`-only variants still render as 「版本 N」), `source_book` = the common book for a same-book group, else none; members get `merged_into = master id` and disappear from list / search / categories / AI (`baseQuery` filters `merged_into IS NULL`) — `GET /api/material/{id}` of a master adds `members`. Ignore = never suggest that set again (restore brings it back). **Unmerge** (or deleting a master) clears the members' `merged_into` and deletes the master; its suggestion returns to DRAFTED / FOUND |
| `GET /api/material/candidates?status=PENDING&extractId=` · `GET /candidates/count` · `POST /candidates/save {items:[{id, ...edits}]}` · `POST /candidates/ignore {ids}` | Candidate inbox; `duplicateOf` flags a same-category same-title material already in the library |

## Python: extraction, material steps, merge

### Novel extraction (implemented)

- `POST /api/models/verify` `{baseUrl, apiKey, model, protocol?}` → `{ok, latencyMs, message, reply}`; `POST /api/models/list` `{baseUrl, apiKey, protocol}` → `{ok, models, message}`.
- **API protocol** (`ModelConfig.protocol`, sent by Java's `AiServiceClient.modelBody`): `openai` (default) or `anthropic` — `_post_chat` converts the OpenAI-shaped payload to Messages (`{baseUrl}/v1/messages`, or `/messages` when the URL ends with `/v1`; `x-api-key` + `anthropic-version`; system messages → `system`, same-role neighbours merged, temperature clamped 0–1, no `top_p` / JSON mode) and the response back (`choices[0].message`, `finish_reason` length on `max_tokens`, usage incl. cache reads), so every caller stays OpenAI-shaped. Checked 2026-11-02 against DeepSeek's Anthropic endpoint (`https://api.deepseek.com/anthropic`).
- `POST /api/extract/jobs` `{fileId, fileExt, model:{baseUrl, apiKey, model, concurrency} | local:{baseId, chunkChars} | gguf: true, materials?, resumeKey?}` (exactly one model source) → job; `POST /api/extract/compile/jobs` `{fileId, entities[], chapters[{title, summary}], plot, model | local | gguf, resumeKey}` → job in the same single-worker queue (progress / cancel via the jobs endpoints below; result `{materials, stats, usage, model, source}`); `GET /api/extract/checkpoints/{key}` → `{exists, stages{pass1, pass2, cards, systems, arcs}, running}`, `GET /api/extract/checkpoints/{key}/chapters?since=N` (逐章查看, `chapter_scan.live`; checkpoint file `chapters.json` + in-memory `extract_checkpoint.READING`), `POST /api/extract/split-preview {fileId, fileExt}` · `POST /api/extract/chapter-text {fileId, fileExt, index}` (`extractor.load_book` caches the last 2 split books), `POST /api/extract/checkpoints/{key}/delete` (400 while in use); `GET /api/extract/jobs/{jobId}` → `queued/running/succeeded/failed/cancelled`, `progress`, `message`, `error`, `result` (incl. `model`, `source` local|api); `POST /api/extract/jobs/{jobId}/cancel`; `GET /api/health`.
- **Local extraction** (`app/local_extract.py`, `LocalSession`): base model loaded via `inference.load(..., from_generation=True)` (not reloaded when already resident; an attached adapter is disabled per call), chunks run strictly serially through `inference.chat_generate` (temp 0.2, ≤900 tokens, +400 with materials), same prompt as the API (`llm_client.build_chunk_prompt`); output parsed leniently (`parse_lenient`: code fences, trailing commas, per-field regex salvage), an unparseable chunk is skipped. Refused while training holds the GPU or a chapter job runs; while it runs, `inference.extract_busy()` makes chapter generation / polish, local AI 构思, model load / unload and training (via `unload`) wait or refuse.
- `app/llm_client.py`: OpenAI-compatible `POST {baseUrl}/chat/completions` with `Bearer` key. OpenCode Go / Console endpoints (host `opencode.ai`) additionally send `x-opencode-session` (stable per task / conversation: `ses_` + 32 lowercase hex, generated once per `ModelConfig`) and `User-Agent: novel-nan/1.0`, because Go rejects requests without the session header with `400 MissingSessionID`; the 「模型配置」 preset `opencode-go` points at `https://opencode.ai/inference/go/openai/v1`. Background jobs (extraction / compile via `extractor._chat_fn(stop=...)`) pass their stop event as `chat(cancel=...)`: the request runs in a daemon thread, the stop flag is checked every 0.5 s and the whole call is capped at the timeout (httpx's timeout is per read, so a busy server trickling bytes could hold a call — and a 「正在取消…」 — for minutes); cancel → fatal `LLMError`, retry back-off also waits on the flag. `chat()` (all structured JSON calls: extraction, compile, merge drafts, profile, crawler AI) sends `thinking: {type: disabled}` to remote APIs by default (`think=False`) — reasoning models count thinking tokens against `max_tokens` (deepseek-v4.1-flash: ~1800 per chapter, truncated JSON); a provider that rejects the parameter (400 / 422 mentioning it) is remembered in `_NO_THINKING_PARAM` and the request resent without it. `complete()` (creative writing) is unchanged. `add_usage` also counts `reasoningTokens` and `truncated` (`finish_reason: length`). Friendly errors (401/403 key, 402 balance, 404 model/URL are *fatal* and abort the job; 429/5xx/timeouts retry ×2). Falls back without `response_format` if a provider rejects JSON mode. Local hosts skip the system proxy; remote hosts use it.
- Jobs are in-memory and run one at a time; Java is responsible for persisting results.
- Languages: Chinese (primary) and English novels. Analysis text is always output in Simplified Chinese; character/place names keep the original spelling.
- All `httpx` calls to local services use `trust_env=False` — a system proxy (Clash etc.) otherwise turns `localhost` requests into 502.
- **Material steps ① / ②** (`app/material_facts.py`). **① `scan`** (extraction with `materials.enabled`; optional chapter range `materials.fromChapter / toChapter` (1-based, 0 = to the end; result `range {from, to, total, chars}`, `chapters` / `chapterCards` hold only that range, `ci` counted from its start; golden chapters = the book's first 3); `app/chapter_scan.py`, since 2026-11-02 — design `docs/素材提取改造方案.md` §3.0 / §3.0.2): **one call per chapter, strictly in chapter order** (no merging of short chapters; API concurrency is not used for reading). Chapters longer than the limit (API 20000 chars, GGUF `chunkChars × 2`, in-app local `chunkChars`) are split at paragraph boundaries, read in order and merged into one chapter card. Each prompt carries a **rolling context** chosen in code: the previous 2 one-liners, known entities whose name / alias occurs in the chapter (≤15, only new facts asked), the lead + current state, open threads `T<n>` (≤20; plant ids assigned in code, advance / payoff must cite an id). One call returns entities + facts and the **chapter card**, by `materials.depth`: `fast` (oneLine, events), `standard` (default: + hooks pos × 7 types × strength, payoffs 11 types × strength × amplified × setup, threads plant/advance/payoff, function, emotion, lead / leadChanges, relations, entityMoves, lines ≤3; first 3 chapters + `golden`), `deep` (+ `nodes`, paragraphs numbered `[n]`, ranges fixed in code). Quotes are checked in code (`Source.locate`: normalised substring or ≥60 % char-trigram overlap; ≥4 chars): unverified facts go to the entity's `unverified` (≤10), unverified card items keep the item with `quote: ""`, `verified: false`; lines must match exactly or are dropped; every verified quote stores `at` = offset in the chapter text. A failed chapter is recorded and skipped, retried once after the book, 5 failures in a row stop the job (INTERRUPTED). `rounds: 2` (**default**, back from 1 after the 2c measurement on 2026-11-03: 1 round found 65–78 % of the entities and 35–49 % of the facts) re-reads in order with all known entities, entities only (`pass2`). Output budget per call (`chapter_scan.max_tokens`): API = base + per-char (fast 800 + 0.9, standard 1200 + 1.3, deep 1500 + 1.6, supplement 800 + 0.9; ≥ the old fixed 1500 / 3000 / 3600 / 1500, ≤ 8000) — fixed caps truncated long chapters; local / GGUF keep 1000 / 2000 / 2400 / 1000. Aggregation in code (`Book`): category + `_norm_title` of name / aliases, facts deduped by char-bigram overlap. Result: chapters (summary = oneLine + first 3 events, events from the card), `entities [{key, category, name, aliases, facts[{fact, quote, chapter (title), ci (chapter index), at}], unverified[]}]`, `chapterCards[ci]` (status done / failed / empty, card fields, `stats` {chars, paragraphs, avgParagraph, dialogRatio, appear, newEntities}), `threads`, `lead`, `pacing` (`app/breakdown.py`), `preface`, `splitWarnings` (most facts first; the user may delete entities in 实体档案), `factStats {rounds, chunks, failedChunks, factsVerified, factsUnverified, entities}`, `usage`. **② `compile_cards`** (`extractor.compile_job`, input = entities + chapter summaries, `_internal` maps facts back to chapter indexes by `ci` or title): ≥2 facts one call each, 1-fact entities 5 per call → `{useful, title, subtype, summary, detail (100–300), attributes (category template), usage → 作者用法, borrowTip → 借用提示, tags}` (prompt: only the given facts, no invented causes, omit unsupported attributes; values like 「无 / 未提及 / 无明确信息」 are dropped by `_EMPTY_VALUE`); `useful: false` is skipped (`notUseful`). World cards sharing a subtype (≥3) get an extra **体系卡** (subtype 体系, `parts`). **Plot arcs** (`plot: true`): chapter summaries (consecutive identical ones = one block, listed once), 20-chapter windows overlapping 3 → `{title, start, end, function, cause, conflict, turn, result, borrowTip}` with roles abstracted (no proper names), deduped by title / >50 % range overlap. Candidates: `candidateId = sha1(entity key)`, `detail`, `facts[{fact, quote, chapter}]`, `aliases`; saving a candidate copies `detail` and puts `facts` into `material.source.facts` (`components/material/FactList.vue`). Compile stats `{entities, cards, notUseful, systems, arcs, failedCards}`. Model calls go through one `call(messages, max_tokens)` (API / GGUF via `llm_client.chat`, in-app local via `LocalSession.chat`); truncated JSON is repaired back to the last complete object (`_close_truncated`). **Checkpoints** (`app/extract_checkpoint.py`): `data/extract-cache/<key>/meta.json` (fingerprint — scan: file, chars, chapters, jobs, `mode: serial-v1`, `cardsV`, depth, max chars, rounds, categories, focus; `pass1` = one row per chapter / part keyed `ci` or `ci:part`, replayed in order on resume; compile: hash of entity keys + fact counts, plot, chapter count; a mismatch wipes it) + `pass1|pass2|cards|systems|arcs|chunks.jsonl` (one fsynced line per block / card batch / window; torn lines skipped). Measured with GGUF Qwen3-4B Q4 on the RTX 4060 Laptop (《耐瑟瑞尔》 ch. 1–6, 13.6k chars): ≈ 16 s / 1000 chars per reading round and ≈ 18 s per card (2 rounds found 27 entities vs 12 with 1 round, 119 verified / 13 dropped facts) — a 3-million-char novel takes ~14 h per round, so pause / resume matters; compiling cards with a 大模型 is ~1 元 per book. **Eval**: `.venv/Scripts/python scripts/extract_eval.py --text x.txt --chapters 1-10 --run g1=http://127.0.0.1:8002/v1,1 --run g2=…,2 [--run ds=https://api.deepseek.com,1,deepseek-chat,DEEPSEEK_API_KEY] [--baseline ds]` runs scan + compile per group and compares time (reading / total), tokens, verified / dropped facts, cards and entity recall against a baseline, printing the top entities' cards side by side.

- **Merge** (`app/material_merge.py`): `POST /api/materials/merge/groups {modelId?, items[{id, category, title, text}], threshold (0.82), maxGroup (6)}` — per category, pair score = content cosine, or max(content, (content + title cosine) / 2) when the titles' vectors are ≥ 0.85 alike (two books' 「狼人」 differ in content, not in name), +0.08 when normalised titles are equal / contain each other; pairs ≥ threshold are merged greedily (best first, group ≤ maxGroup, every new member ≥ threshold − 0.08 to all members, so chains don't snowball) → `{groups[{ids, score, minScore}], total, model, ms}` (≤500). Measured on a toy set with bge-small-zh: two differently written 「狼人」 = content 0.72 → score 0.94; 「狼人族」 joins at 0.80; 「吸血鬼」 stays out. `POST /api/materials/merge/draft {category, members[{id, book, title, subtype, summary, attributes, detail}], model | gguf}` — one JSON call: `same` (which members are the same thing), master `title / subtype / summary / detail / attributes / tags`, `variants {id: 这本书独有的具体设定}`; the draft keeps every member as a **可选版本** (`variants {n: {label ≤8 chars, note ≤80 chars}}`, same-name-different-thing allowed) and puts only the commonality on the master. **Grounding** (char bigrams, `_grounded`, 40 %): master attribute values and detail sentences must be supported by **at least two members' own texts** (else dropped → `droppedAttributes`; a one-member detail is that version's, and would otherwise leak into 「只用另一版」); a version's `note` must be supported by that member (else emptied) and its `label` share a bigram with it — the 4B GGUF otherwise pads the master with invented 外形 / 能力 / 与人类的关系.
