# Frontend: rules, settings editor, workspaces (书房)

> Split out of `CLAUDE.md` on 2026-11-03 (content moved verbatim). `CLAUDE.md` keeps the overview and conventions; keep this file updated when the APIs / behaviour below change.

## 5. Frontend Conventions (`frontend/`)

### Commands

```bash
npm install
npm run dev        # http://localhost:5173 → backend 8022 (.env.development)
npm run dev:test   # http://localhost:5174 → test backend 8012 (.env.test)
npm run build      # production build
npm run preview
```

### Rules

- All SFCs use **`<script setup>`** (Composition API); UI text is Chinese, identifiers/comments may be Chinese or English.
- `@` alias → `src/` (configured in `vite.config.js`).
- Keep HTTP calls inside `src/api/*.js` using the shared Axios instances: `request` (Java) and `aiRequest` (Python, `VITE_AI_BASE_URL`, fallback `http://localhost:8021`, 180s timeout — only for `/api/local/**`) (`src/api/request.js`; Java `baseURL` from `VITE_API_BASE_URL`, fallback `http://localhost:8022`, 60s timeout). Views must not create their own Axios instances.
- API helpers unwrap `res.data`; callers treat `response.code === 0` as success.
- Routes are lazy-loaded (`() => import(...)`) with `meta.title` / `meta.icon` consumed by the sidebar; register new pages in `src/router/index.js`. A menu entry with `meta.children: [{path, title, icon}]` renders as an `el-sub-menu` (`layout/Sidebar.vue`); the parent route only redirects (e.g. 小说抓取 → `/novel/crawl/config`).
- Element Plus and all its icons are registered globally in `main.js`.
- Layout: `.app-wrapper` is fixed to one screen (`height: 100vh; overflow: hidden`); only `.app-main` scrolls, so the sidebar stays put. Scroll-to-top must target `.app-main`, not `window`. **Route pages need exactly one root element — no HTML comment before or beside it**: `AppMain` wraps them in `<transition mode="out-in">`, and in dev a top-level comment makes a fragment root, so leaving that page leaves the next one blank (happened 2026-11-02 when exiting the 书房).

### Novel settings editor (`SettingsEditor.vue`, used inside each workspace)

- **Theme** (site-wide since 2026-11-02): `styles/ink-theme.css` (墨色 + 朱砂红) sits on `:root`, so every page and teleported popovers / dialogs / message boxes use it. It overrides Element Plus color variables (primary `#b03a2e` (朱砂红; was the darker `#7a3028` until 2026-11-02) + light / dark steps, success = ink green `#4f7a52`, text, border incl. dark / darker, fill, bg, `--el-font-family`) and defines `--ws-paper / card / soft / ink / sub / line / accent / radius`, sidebar `--ws-side / side-hover / side-text / side-active-bg` (`layout/Sidebar.vue`: paper-white, active item = light red background + red bar on the left) and fonts `--ws-font-ui` (system, forms / tables / buttons) / `--ws-font-title` + `--ws-font-prose` (霞鹜文楷, npm `lxgw-wenkai-webfont` regular only, sliced by unicode-range, imported in `main.js`; used for card / dialog / drawer headers, h1–h3, chapter text, `SpecTree` values, `IdeaCard` sections; no synthetic bold). `.app-main` gets the paper colour + a faint CSS dot texture. **Don't hard-code Element default colours** (`#409eff`, `#303133`, `#606266`, `#909399`, `#f5f7fa`, `#e4e7ed` …) in components — use `var(--el-…)` / `var(--ws-…)`. `SettingsEditor`'s `--se-*` read `--ws-*` with fallbacks.
- **Lists & ladders** (redesign step 3): group fields other than `characterCards` render as `GroupCardGrid.vue` (numbered cards with name + 「第 N 章起」 / 素材库 tags + 2-line preview; click → the item's full form below the grid with 出场条件 / 复制 / 删除 / 完成; 「AI 生成 N 个」 in the header); `powerSystem` text with numbered lines (`1. 名：说明`) renders as a ladder (`ladderOf`, colour deepens per level); tags render as chips when every tag ≤ 14 chars, else as a bullet list.
- **Field AI = four ways** (`components/ai/AiRegenButton.vue`, replaces the old 「AI 润色」/「AI 生成」 pair on text / textarea / tags): one 「AI 生成 / AI 重新生成」 popover with an optional 方向 box and 「参考已有内容」 (checked by default when the field has content) → `aiFillField(field, …, {direction, keep})` (old `'polish' | 'generate'` strings still accepted): text + keep = `action: polish` (seed = box text) + `direction`; text without keep = `generate` with seed = direction; tags + keep = `keepValue` → Python asks only for **new** items and the frontend appends them (asking for the full list made the model rewrite the existing ones); tags without keep confirm before overwriting. Busy key `…|ai`.
- **Layout** (2026-10-30 redesign, step 1+2): category nav (progress dot: empty / part / ≥60 % filled) + main area; header = `#lead` slot (workspace puts 作品定位 there) + ⓘ hint + AI 填写设置 + `#actions` (保存) + 「更多」 (从素材库添加 / 查看 AI 看到的设定 = drawer, replaces the old right preview column / 查看 JSON / 编辑结构 = the old 编辑模式 / 重置). Filled fields render as read-only content cards (`SpecTree compact`, 2-column grid, `grid-auto-flow: dense`; textarea / group / choice with an expanded sub-option span both columns); click → the normal `OptionField` with 「完成」; filled groups stay open; empty fields are chips under 「还可以补充」. Tag fields with long items (world rules) span both columns like textareas. 编辑结构 shows every field as a form like before. Field AI buttons appear on hover / focus only.
- **Schema-driven**: everything renders from data — `categories[] → fields[] → options[] → children(fields[])`, nestable to any depth. Field types live in `src/novel-options/fieldTypes.js` (`single`, `multi`, `text`, `textarea`, `number`, `slider`, `tags`, `group`); to add a type, register it there and map it in `OptionField.vue`.
- **Data source**: `src/api/novelOptions.js#getOptionSchema()` currently returns `src/mock/novelOptionSchema.js` (built-in categories 世界观/角色/情节推进/文风, `elementTemplates` such as 怪物/势力/种族/地点/物品/功法, `genericSuggestions`). When the DB exists, switch only this function to a backend call returning the same shape.
- **Values**: `{ [categoryKey]: { [fieldKey]: value } }`; choice value `{ selected: string[], sub: { [optionValue]: childValues } }`, group value `[{ _id, ...childValues }]`.
- **Extensibility (编辑模式)**: users can add custom options inline, add fields to any category / group / option (from suggestions or self-defined), and create custom elements (e.g. 怪物) from a template or blank. User-created items carry `custom: true` and `uid()` keys.
- **Confirmed vs default**: `number` / `slider` fields always hold a value, so they count only after the user changes them (`markTouched` → `container.__touched[fieldKey]`); untouched defaults never reach `buildSpec()` and therefore never become generation constraints.
- **角色卡** (`characters.cast` has `display: 'characterCards'` → `CharacterCards.vue`): character.ai-style cards (avatar, 一句话人设, role / gender / age, collapsed preview of personality / speech / greeting), fields paged by `section` (基本信息 / 性格与说话 / 内心 / 经历与能力 / 其他). 「AI 创建角色」 from a one-line concept (`genItems(..., concept)`), 「AI 补全」 one card (`ai.fillItem`), 「试聊」 (`CharacterChat.vue`, `kind: chat`; greeting opens the chat, optional scene / user role, regenerate, 「存为示例对话」 appends to the card's 示例对话). Saved configs carry `schemaVersion`; `schema.js#upgradeConfig` adds new built-in group sub-fields to older workspaces once.
- **Material pick before every AI fill** (`SettingsEditor.pickMaterials`): every settings AI button that writes content — field 「AI 润色」/「AI 生成」 (text, textarea, tags), group 「AI 生成 N 个」, 「AI 补全本分类」, character card 「AI 创建角色」 / 「AI 补全」, `ChoiceWidget` custom option AI — first opens `MaterialPicker` (`action-label` mode: 取消 = no request; 「不用素材，直接…」 = `materialIds: []`, only the input box; 「用 N 条素材…」). The request then sends exactly the picked ids with `autoMaterials: false`. 「AI 填写设置」 materials are **preselected** in the picker; its 「自动匹配」 switch makes the picker run the local retrieval (query = position path + box text + 补充要求) and precheck up to 5 results with relevance ≥ 30 (top 5 when not reranked). 试聊 and 「AI 给几个方向」 don't open the picker. `MaterialPicker` shows, under a selected multi-version material, 用法 让 AI 选 / 只用①… / 融合 (stored as `variant` on the picked object, defaulting to the hit version from vector search; callers send `api/material.js#materialVariants(list)`; 「从素材库添加」 expands it with `materialApply.resolveVersions` — chosen version = 共性 + that member, else 共性 + an 「可选版本」 list in the note); it has 关键词 / 向量检索 modes (selection kept across modes, `initialSelected`, `vectorQuery`, `autoVector`, `feedbackContext`); the 素材库 page has a third mode 向量检索 with 已向量化 N / total + 「全部向量化」; the chosen vector model id is shared via localStorage `nan_novel.material.vectorModel` (`api/material.js#getVectorModelId`).
- **AI 填写** (when the workspace passes `novel-id` + `ai`): since 2026-11-01 the two buttons below are one `AiRegenButton` (see «Field AI = four ways»; 参考已有 = the old 润色, no 参考 = the old 生成 with an explicit 方向). Originally text / textarea fields had two buttons — 「AI 润色」 (`fill.action: polish`, `seed` = the box text, required: keep everything written and expand it, textarea ~2–3× up to 400 chars) and 「AI 生成」 (`action: generate`, `seed` = optional rough direction, writes new content) — explained in hover titles and in `AiFillSettings`; tags only have 「AI 生成」; **single / multi fields have no header AI button** (picking an existing option was useless) — their AI lives in `ChoiceWidget`'s 「自定义」 panel: option name input + optional description (shown as the option tooltip) + 「选素材」 (`MaterialPicker` pick-only; these materials apply **only** to this custom option: sent as the request's `materialIds` with `autoMaterials: false`, the 「AI 填写设置」 materials are not used) + 「AI 润色」 / 「AI 生成」, both enabled only when the input has text or materials are picked → `ai.customOption` → `fill {mode: option, action, seed}` → Python `_custom_option` returns a draft `{option: {label (≤12 chars asked), desc}}` the author edits, then 「添加并选中」, 「AI 生成 N 个{itemLabel}」on groups (e.g. 关键情节节点 with 节点名称 / 所处阶段 / 情节描述), 「AI 补全本分类」for the unfilled fields of a category. Number / slider fields are generation parameters and never AI-filled. Shared settings in the header popover `AiFillSettings.vue` (model: 大模型 / 本地 + adapter, 补充要求 with 「AI 给几个方向」, materials picked or AI-matched, blocked source books). Requests go to Java `/api/novel/gen/{id}/ideas` with `kind: fill` and `fill {mode: field|items|category|option, path, fields (schema + option labels), current (filled siblings), itemLabel, count, existing}` plus the editor's **unsaved** `spec`. `novel-options/aiFill.js#applyValue` writes results back (choice labels → option values; unknown labels become custom options via `addOption`). Concurrency (`aiRunning` key → scope path, `ai.loading(key)` / `ai.locked(scope)`): **local model = one request at a time** (one model on the GPU, generation serialised); **API model = parallel**, only buttons whose scope overlaps a running one are locked (`aiFill.scopesOverlap`: one path is a prefix of the other — e.g. 「AI 补全」 on a character card locks that card's fields and 补全本分类 of 角色, not other cards; new-item generation uses `[...group, NEW_ITEMS]` so it doesn't block existing items). Overwriting a filled choice / tags field asks first; text writes show a notification with 「撤销」.
- **Output**: `buildSpec()` → `[{key,label,type,value,display,children}]` (`type: 'option'` for sub-option containers, `'groupItem'` + `name` for group entries) is what the workspace saves as `settings.spec` and the backend turns into constraints; `getConfig()` (`{categories, values}`) is saved as `settings.config` to restore the editor.

### Novel workspaces (`/novel/create` → `/novel/workspace/:id`)

- **Model sources** everywhere AI is used (workspace, AI 构思, AI 填写, 小说提取, polishing): `api` = 大模型 (Java「模型配置」active + VERIFIED config, auto-detected via `/api/ai/model/list`; none → prompt with a link to 模型配置), `local` = 本地模型 (safetensors base + optional LoRA adapter, trainable), **`gguf` = the GGUF model currently running on the 「llama.cpp」 page** (option disabled while llama is not running — `api/localModel.js#runningLlama`; Python resolves it with `llama.api_config()` → `ApiChatGenerator` / `llm_client`, no key, no Java config; chapters / recheck go straight to Python like `local`, AI 构思 / 填写 send `source: gguf` to Java which forwards `gguf: true`, extraction sends `model {source: gguf}` → Python `ExtractRequest.gguf`; serial like `local` because of `--parallel 1`; chapters record `{source: gguf, name}`; no adapters / polish), `remote` = 远程模型 (remote GPU base + adapter) — **reserved**, shown disabled「即将支持」and rejected by the backend.
- List page creates a workspace with just a title and context window (8192 / 32768); the model is **not** chosen there — it defaults to the configured 大模型, else the default local model (Qwen2.5-1.5B-Instruct), and is switched freely inside the workspace. It shows the default-model check with a one-click download (`/api/local/models/download` → `models/base/<id>/weights/`) and Hugging Face / hf-mirror links.
- **Using materials**: `SettingsEditor` → 「从素材库添加」 opens `MaterialPicker` (category / keyword / tag filters, preview of where each item goes). `novel-options/materialApply.js#APPLY_TARGETS` maps categories to settings (monster/faction/location/item → custom element from template, auto-created if missing → its list; character → 角色·主要角色; plot → 情节推进·关键情节节点; world → 世界观补充). Applying **copies** the data (later library edits don't change the story); group items get `_fromMaterial` (shown as「来自素材库」, never exported by `buildSpec`), unmapped attributes go into an added 备注 field.
- Workspace header switches the model source (大模型 / 本地模型) at any time, also after chapters exist (each chapter records the model that wrote it), and, for local, the base model (clears the adapter). It also has an adapter select (only adapters with `compat: ok` and `matchedBaseId` = the base) (saved as `model.adapterId`; 「加载模型」 then loads base + adapter, or only switches the adapter when the same base is resident). `modelReady` requires the loaded `adapterId` to equal the workspace's.
- **The workspace page is kept alive (`AppMain` keep-alive) and reused across workspaces**: any tab component holding per-workspace state must be keyed by the workspace (`:key="novel.id"` — `SettingsEditor`, `PlanWizard`, `IdeaPanel`) or watch `novelId` (`FactsPanel`, `WorldBook`). Until 2026-11-01 `PlanWizard` / `IdeaPanel` weren't keyed: switching workspaces kept the old plan draft on screen and its autosave wrote it into the new workspace (3 real workspaces got the same draft). `PlanWizard` additionally only saves to the workspace whose draft it actually loaded (`draftOwner`).

Ink-wash background = two self-drawn blurred SVG mountains on `.study::before/::after` (`styles/ink-theme.css`, also `--ws-glass` and `.study-nav-item`). - **AI 构思** (`IdeaPanel`): a 「使用说明」 popover (top right, `MANUAL_COLS` / `MANUAL_ROWS` — keep in sync with what each request sends) lists which inputs every AI action uses. Inputs: model (大模型 / 本地模型 + adapter); **设定** categories (every category of the settings editor incl. custom elements, re-read via the workspace's `readSettings()` each time the tab opens; none selected by default, remembered in localStorage `nan_novel.ideaSettings.<id>`; **后续走向** 「AI 构思后续走向」 (`kind: story_direction` = 走向引擎, 5 per click, ~25 s, appended so it can be repeated; context = the **world book** — the 设定 / 章节 checkboxes don't apply; cards show 驱动 tag, 合理 / 精彩 scores, 用到, 「已按审稿修正」 (hover = original) or yellow problems;
