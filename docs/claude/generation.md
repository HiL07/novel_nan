## Java: generation / planning / inspiration APIs

### Novel generation API (`NovelGenController`, `/api/novel/gen/**`)

Only the generation calls that need the **API model's key** or the **material library** go through Java; everything else under `/api/gen/**` is called by the frontend directly.

| Method & path | Purpose |
|---------------|---------|
| `POST /api/novel/gen/{novelId}/chapters {goal, title?, targetChars?, polish?{enabled, baseId, adapterId}}` | 大模型 workspace: attaches the active verified config (`requireActive`, none → 400) as `api` and forwards to Python `/api/gen/novels/{id}/chapters`; returns the Python job |
| `POST /api/novel/gen/{novelId}/chapters/{index}/recheck {digest?, review?}` | 大模型 workspace: same, forwards to Python `.../chapters/{n}/recheck` (re-extract story facts / re-check consistency) |
| `POST /api/novel/gen/{novelId}/ideas {kind: title\|outline\|chapter\|fill\|direction\|hint_polish\|chat\|story_direction\|situation, source?: api\|local, baseId?, adapterId?, hint?, tone?, rejected?[], chosenDirections?[], chapterContext?{current, past}, count?, purpose?, materialIds?[], materialVariants?{materialId: blend\|memberId}, autoMaterials?, query?, excludeBooks?[], fill?, chat?, spec?}` | AI 构思. **Multi-version materials** (merged masters): Java attaches `variants[{label, book, note, summary, attributes}]` from the members and `variantMode` — `auto` (default: all versions, model picks one), `blend` (all, combine into one), `fixed` (only the chosen member; also set automatically when auto-matching hit a version, `usedMaterials[].variant` = its label); Python `ideas._material_lines` writes them as ①②… lines with the matching instruction (fixed: a master summary listing versions and the master tags are left out; near-duplicate note / summary written once). `story_direction` = **走向引擎** (`directions.generate`, `docs/走向引擎.md`: world-book snapshot → 5 drivers × 2 candidates → review call scores / revises → ranked, ≤2 per driver) → `{directions[{label, direction, driver, driverLabel, uses, scores{reasonable, exciting}, problems, revised, original}]}` + `situation` + `checked`; `situation` = 整理人物局面 into the ledger (`directions.refresh_situation`, also run automatically before the first `story_direction` when no character has a goal); `direction` = 构思方向 suggestions `{directions[{label, direction}]}` (seeded by `hint`, `purpose` says what they are for — now only used by AiFillSettings 「AI 给几个方向」); `hint_polish` = expand the author's 构思方向 (`hint` only — no settings / chapters / materials) into a full 构思 → `{text, changes}`; `chat` = character roleplay `{reply}`. `excludeBooks` drops blocked books' materials from both picked and auto-matched ones (pinned kept; `blockedMaterials` = how many picked were dropped). Java loads the picked materials (`MaterialService.listByIds`, ≤ 20) and, with `autoMaterials`, adds local `vectorSearch(query or hint)` results (hybrid + rerank, no LLM): reranked → relevance ≥ `RERANK_MIN_SCORE` (30); no reranker → the top 3 (`AUTO_UNRANKED`). `source=api` attaches the config; `local` forwards `{baseId, adapterId}` instead. Returns `{kind, nextIndex, result, usage, model, usedMaterials[{id, category, title, score, reason, auto}]}` — suggestions only, nothing saved |

- Fields are whitelisted before forwarding. Python's 422 bodies echo the request (incl. the key): `NovelGenService.pythonMessage` passes through only our own `{message}` and never logs response bodies.
- `NovelGenService.materialItems(ids, variantChoice)` (+ `parseVariants`) builds the Python material items (incl. multi-version `variants` / `variantMode`) for AI 构思 and the inspiration wall.

### Auto planning API (`NovelPlanController`, `/api/novel/plan/{novelId}/**`)

一句构思 → 设定 + 10 章大纲 + 伏笔计划 (design in `docs/自动规划.md`); **planning only, never chapter text**. One route, **story-first** (no material library needed; the material-first route — `/needs` → `/retrieve` → material-adapted `/settings` — was removed 2026-11-02; `mode` is ignored) = `/idea` → `/settings` (world + 主角 only; `/settings-part` per block, module `lead` = 主角) → `/book` + `/cast` (supporting cast, elements, stage table) → apply without an outline (since 2026-11-01 the UI stops there; `/enrich` / `/outline` / `/review` remain for later use) (order changed 2026-11-01: the skeleton used to come before the settings and invented rules the settings didn't have). Requests carry `bookConfig` (写作参数), `idea` (the chosen 灵感) and `book` (全书骨架); the premise may be empty when `idea` or `book` is given (`NovelPlanService.story`). Model = `{source: api, configId?} | {source: gguf} | {source: local, baseId}` (`resolveModel`), Python `/api/gen/plan/*` via `InspirationService.callGen` → `AiServiceClient.genModelCall`.

| Method & path | Purpose |
|---------------|---------|
| `POST /idea {premise?, directions?[], bookConfig?, tone?, conditions?, count? (1–5, 3), feedback?[{dislike, want, rejected[]}] (≤10), materialIds? (portable versions only, others dropped; each idea then carries `materials[{id, title, used}]`, source numbers checked by code), model}` | story ① `planner.idea` → `{ideas[{title, core, situation, conflict, payoff, hook}]}` (clearly different from each other); `feedback` = every 「说说原因再生成」 so far (`feedback_text`: 希望 = must, rejected ideas must not come back) |
| `POST /assist {kind: direction\|style\|conditions\|premise\|sellingPoint, text, premise?, conditions?, directions?, bookConfig?, materialIds? (not for direction; style uses craft ones only; text may be empty for sellingPoint and with materials; rejected when the author filled nothing — see `docs/自动规划.md` §7.10), model}` | small helpers on the 参数 · 灵感 step (`planner.assist`, plain text, ~1 s): direction / style → a label ≤7 字 (`_short_label` cuts at the first comma), conditions → the author's own requirements one per line (nothing added), premise → polished idea ≤100 字 → `{kind, value}` |
| `POST /book {premise?, idea?, bookConfig?, settings?, volumePlan?[] (one line per volume), volumeCount? (0 = AI, ≤8), pace?: slow\|normal\|fast, tone?, conditions?, book?, regen?{index, instruction?}, model}` | story ③ `planner.book` (after the settings: prompt carries 【设定】 and forbids inventing rules / ranks; 【作者定的分卷方向】 from `volumePlan` / `volumeCount` / `PACES`) → `{book{titleOptions, logline, storyHook, sellingPoints, worldPoints, volumes[{title, summary, chapters, stages[{title, chapters, goal, startState, endState, power, mustHappen[], forbidden[], tierMax}]}]}, issues (book_issues + invented_issues: a rank like 「二阶」 whose unit the settings never use), stages (= `book_stages`, the new 阶段表), extended, regenerated}`; total chapters ≈ `targetWords ÷ chapterWords` (else 300), first stage tierMax ≤ 2; with an existing `book` = keep it and append 1–2 volumes; `book` + `regen` = only that volume is rewritten (neighbours' end / start states in the prompt), the others are kept verbatim |
| `POST /settings-part {settings, module: rules\|note\|power\|abilities\|mechanics\|resources\|characters\|elements, category? (elements: faction\|location\|item\|monster), direction?, keep?, idea?, bookConfig?, book?, model}` | one settings block regenerated, four ways = direction given / not × `keep` (existing block in the prompt: keep it, supplement / modify, no repeats) → `{module, category, value, keep, related[{module, category, label, term}]}`; with a direction the other blocks are listed by key (`_blocks_text`) and the model reports sentences contradicting the direction (`conflicts` → `conflicts_of`), shown in the wizard with 「用同样的方向重来」 |
| `POST /cast {settings, book, premise?, idea?, bookConfig?, model}` | story ③b after the skeleton: `planner.cast` → `{characters (supporting only), elements, stages (= book_stages), issues (cast_issues: thin / tier over the stage's tierMax / mustHappen names without a card)}`; appearFrom inside the stage that first needs it |
| `POST /enrich {settings, premise?, idea?, bookConfig?, excludeBooks?, stage?, model}` | story ④ (optional) every draft character / element (≤12, order = `planner.enrich_targets`) is a local retrieval need (`retrieveNeeds`, only hits ≥ `RERANK_MIN_SCORE`, ≤2 each) → `planner.enrich` → `{suggestions[{target, kind, index, name, suggestion, fields (only that object's own field keys), sources, leaks}], materials[{id, title, book, category}], searched}`; no hit → no model call |
| `POST /settings {premise?, idea?, bookConfig?, book?, materialIds?, materialVariants?}` | story ② world + 主角: `planner._settings_story` (materials only as optional reference — the UI sends none, world adds (no `cards` and no `title` since 2026-11-01 — they overlapped the rules / the idea title) `power{intro, realms[{name, desc, cost}], beyond}`, `abilities{innate, acquired, dimensions}`, `mechanics[{title, desc}]`, `resources[…]`; `stages` computed from the skeleton by `book_stages`; extra `story_issues` thin / book) → `{draft{world, characters[主角], elements, stages}, issues}` |
| `POST /outline {premise?, …, settings, materialIds?, count?, book?}` | (not in the UI flow) with `book`: 【当前阶段】 via `planner.stage_block` (stage ends inside → reach endState; else don't resolve early), returns `bookStage`, extra `stage_issues` (mustHappen not found); `{outline{title, logline, synopsis, chapters[{index, title, goal, beats, cast, newTerms, foreshadow[{key, action}], clocks[key], hook, openingNote}], foreshadows[{key P1…, text, plantIn, payoffIn}], clocks[{key K1…, text, due, setIn, dueIn}]}, issues}` (hook / opening ≤3 new names, ≤5 new terms / early appearance / foreshadow) |
| `POST /review {premise?, …, settings, outline}` | (not in the UI flow) `{chapters[{index, problems, revised{title, goal, beats, hook}\|null}], overall, codeIssues}` — the UI adopts revisions per chapter |

- Frontend: workspace tab **自动规划** = `components/novel/PlanWizard.vue` (story-first only — drafts of the removed material route (`mode: material` / numeric `step`) are dropped on load except premise / conditions; steps 参数 · 灵感 (`BookConfigForm.vue` — 文风 has 「AI 生成」 via `components/ai/AiShortGen.vue`, it is also the 基调: the separate 基调 box is gone on this route, old drafts move `tone` into `bookConfig.style`; 创作方向 chips + 「自定义」 (describe → AI ≤7 字 label, kept in `customDirections`); 你的想法 / 补充要求 = `components/ai/AiWandInput.vue` (魔术棒 inside the box: AI 润色 / 整理成一条条, 撤销); a basis note on the right + 「查看这批的生成逻辑」 (`ideaRuns` = input snapshot per batch); 「换一批灵感」 vs 「不满意，说说原因再生成…」 (dialog 不满意 / 希望, all kept in `ideaFeedback` and sent each time); the 「清空这次规划」 button was removed) / 设定 (+ 背景卡 / 力量体系 / 机制 / 资源; every block header has `AiRegenButton` + 撤销, `partUndo`) / 全书骨架 (basis note, 卷数 / 节奏 / 分卷方向 inputs, `BookSkeleton.vue` with 「只重来这一卷」, + 配角 / 元素 / 阶段表) / 写进工作区; the 素材点睛 / 10 章大纲 / 审稿 panes are still in the file but not in the steps; every step editable / rerunnable, 「一键全自动」 = first idea → settings → skeleton → cast, stops before 写进工作区, model via `components/persona/ModelPicker` key `nan_novel.plan.model`). Story-first settings write 世界观 `powerSystem` / `lore` (group 世界背景卡) / `mechanics` / `resources` (schema v4; `schema.js#upgradeConfig` adds v4's plain fields once via `ADDED_FIELDS`). **Tab visibility** (`workspace.vue#planning`, true when the workspace opens without a framework — no book / spec / chapters): only 自动规划 is on the 书房 icon rail (panes stay mounted because apply writes through `SettingsEditor`); `onPlanApplied` sets it false → the other tabs appear and 自动规划 is removed (`v-if`), so framed workspaces never show it. `PlanWizard#autoContinue` (prop `continueSignal`, 「按全书骨架规划接下来 10 章」) has no entry point any more (the prop is not passed). 作品定位 = chips in the 书房 top bar + dialog (`updateNovel {bookConfig}`); 新建工作区 dialog field 「一句构思」 → `/novel/workspace/<id>?plan=…` opens it. `api/novelPlan.js`.

### Inspiration wall API (`InspirationController`, `/api/inspire/**`)

AI integrates the library into concrete ideas (design in `docs/灵感墙.md`). Model = `{source: api, configId?} | {source: gguf} | {source: local, baseId}` (resolved by `NovelExtractService.resolveModel`), Python `/api/gen/inspire/*` via `AiServiceClient.genInspire`.

| Method & path | Purpose |
|---------------|---------|
| `GET /walls` · `POST /walls/save {id?, name, note?, novelId? ('' = unlink), excludeBooks?}` · `POST /walls/{id}/delete` | Walls (latest updated first, `ideaCount` / `materialCount`); delete removes its items and runs, never materials |
| `GET /walls/{id}/items` · `POST /items/save {id?, wallId, type: idea\|material, title, content, sources, note, sort?}` · `POST /items/{id}/delete` · `POST /walls/{id}/pin {materialId}` | Saved ideas and pinned materials (pin is idempotent; items carry the current `material`, null if deleted) |
| `POST /walls/{id}/plan {request, target, conditions, stage?, model}` | ① needs `{summary, needs[{category, query, count 1–6, role opponent\|scene\|prop\|lore, why}] ≤8, explore, stage}`; `explore` = empty request and no linked workspace (code-decided); `stage {phase opening\|early\|mid\|late\|any, tierMax, protagonist, source user\|table\|workspace\|none, chapter?}` = Python `inspire.stage_of` (author's `source: user` stage, else the workspace 阶段表 row of the next chapter, else written ÷ planned chapters; defaults 开篇/前期 2, 中期 3, 后期 5) |
| `POST /walls/{id}/retrieve {needs[+ignoreStage?], explore?, stage?}` | ② local, no tokens: pinned materials first (`from: wall`, never filtered), per need `vectorSearch(query, category, excludeBooks, count×6, keep)` (no MMR — removed 2026-10-29, see `docs/素材检索.md` §7–8) → reranked ≥ `RERANK_MIN_SCORE` else top 3, ≤2 per book per need, deduped across groups. **Stage filter** (`StageFit`): opponent / scene / prop needs drop materials ≥ tierMax+2 **before** retrieval (`hidden` = how many), tierMax+1 sorted last (`relaxed`); lore keeps them but ≤ `FAR_QUOTA` 2 `far` items per run; `ignoreStage` = 「也看看」. `explore` = 2 random per category, round-robin over tier layers (rich ones first within a layer), only ok / unknown ones when a stage is set, ≤2 per book; total ≤24 → `{groups[{need, items[{material, score, variant (hit version id \| auto), matchedLabel, from, tier, fit ok\|stretch\|far\|unknown}], hidden, relaxed}], total, reranked, stage}` |
| `POST /walls/{id}/ideas {request, target, conditions, plan, stage?, materialIds ≤24, materialVariants, count 1–5, model}` | ③ ideas → saved `inspiration_run` with `ideas[{title, pitch, sections[{heading, text, sources}], elements[{category, name, desc, sources, change}], twist, questions, sources (material ids), uncited, farConflict (headings citing a far material while writing 交手 / 击败…), target, sourceRefs[{materialId, title, book, category, variant}]}]`; the wall's latest 12 saved ideas go to Python as `wallIdeas`; material items carry `tier` / `fit` (prompt lines `（量级 N）【远景：只能作为传说 / 背景 / 伏笔…】`) and the prompt has 【故事阶段】 |
| `POST /ideas/refine {wallId, idea, instruction?, materialIds, materialVariants, target, model}` · `POST /ideas/revise {…, instruction, history[]}` | 细化 → `{detail{sections, instruction}}`; 追问改 → `{idea}` (with `sourceRefs`) |
| `GET /walls/{id}/runs` (≤50) · `POST /runs/{id}/update {ideas}` · `GET /browse?wallId=&category=&count=` | Runs; write back refined / revised ideas; 逛素材 (random, ≤2 per book, invalid category → 400) |

- Tables (`sql/inspiration.sql`, also in `init.sql`): `inspiration_wall` (`exclude_books` JSON), `inspiration_item` (`content` / `sources` JSON), `inspiration_run` (`request` / `plan` / `materials` / `ideas` / `usage` JSON).
- 写进工作区 (`components/inspire/ApplyDialog.vue`, wall linked to a workspace): 大纲 = append chapters (numbered after the max outline / written chapter) via Python `novels/{id}/update {outline}`; 设定元素 / 构思方向 go through `sessionStorage` `nan_novel.inspire.apply` (`api/inspire.js#APPLY_KEY`, read once, 10 min) → `workspace.vue#applyInspire` → `SettingsEditor.applyExternal` (elements as id-less materials through `applyMaterial`) / `IdeaPanel.setHint`. IdeaPanel has a 「去灵感墙构思」 link.

## Python: generation

### Novel generation (`app/generation/`, `/api/gen/**`)

`novel.model` = `{source: local, baseId, adapterId?}` (adapter validated with `inference.check_adapter` on create/update) | `{source: api, apiName}` (display name only; the config comes from Java per request) | `{source: remote}` (reserved, rejected). Called directly by the frontend like `/api/local/**`, except 大模型 chapter starts and AI 构思, which come through Java (`/api/novel/gen/**`) carrying `api` (the key lives only in that request / job's memory, never in job status or files).

IdeaPanel's outline has a 「故事账本」 checkbox (`nan_novel.outlineLedger`): per chapter the referenced ledger foreshadows (埋 / 推 / 收, status), clocks, beats / hook, editable refs in the draft |

- **Model interface** (`backends.py`): everything goes through `TextGenerator` (`count_messages`, `count_text`, `tail_tokens`, `context_limit`, `ensure_ready`, `generate(messages, GenParams) → GenResult`). `LocalHFGenerator` wraps `app.local.inference.chat_generate` (chat template + system message, token-level cancel via `StoppingCriteria`, exact `finishReason`). `ensure_ready` requires the loaded adapter to equal the workspace's. `GenParams.use_adapter=False` runs a call inside `disable_adapter()`: chapter summaries and arc merges always use the pure base (continued-pretraining style adapters weaken instruction following); segments use the adapter. Each chapter records `model` (`{source: local, baseId, adapterId}` or `{source: api, name}`). `ApiChatGenerator` = OpenAI-compatible API via `llm_client.complete` (token counts estimated from characters for context assembly; real `usage` recorded; cancel between calls). `source: remote` raises "暂未接入" — a remote GPU backend implements `TextGenerator` and registers there.
- **Polish** (`chapter._polish`): ~300-char paragraph chunks rewritten with the local base + adapter (chat prompt `prompts.POLISH_SYSTEM`, temp 0.4); a chunk is kept unchanged if the output was truncated or its length ratio is outside 0.7–1.4. `originalText` holds the pre-polish text (re-polishing always starts from it); `polish {baseId, adapterId, adapterName, chunks, changed, kept, at}`. The model is loaded with `inference.load(..., from_generation=True)` (bypasses the generation-busy guard for the job's own load); in a local workspace polished with different settings, the workspace adapter is switched back afterwards.
- **Output cleanup** (`chapter._clean`): strips preambles (「好的，以下是…：」, also after a short leading sentence), chapter headings (incl.【第一章 …】), and cuts at echoed prompt section headers (`PROMPT_ECHO`: 【本次任务】【核心设定】…) that small local models sometimes repeat.
- **按章节放行** (borrowed from world books, chapters instead of chat messages): group items may carry `appear {from, span, exclude}` (`_appear` in the editor, `AppearEditor.vue` 「出场条件」, exported by `buildSpec`); `spec.build_for(novel, spec?, chapter=n)` → `apply_chapter` moves cards with `from > n` into `cons.not_yet` (not in prompts; `context.build` reports `dropped.notYet`; `_review` adds `spec.scan_early` 「提前登场」 issues; `ideas._context` lists them as 【后期才登场的设定】), `span` keeps a card while its name occurs in the last `span` chapter summaries, `exclude` words in the haystack drop it. 情节推进 group `stages` (**阶段表**: 章节范围 / 主角实力 / 对手上限 1–5 / 备注; not a card) → `spec.stage_at(spec, n)` → core 【当前阶段】 + the 灵感墙 / AI 构思 tier limit. Old workspaces get the group via `schema.js#upgradeConfig` (SCHEMA_VERSION 3 adds missing built-in groups).
- **作品定位** (`novel.bookConfig`, set by `POST /novels/{id}/update {bookConfig}` or plan apply; `spec.clean_book_config`): `spec.build_for` puts 【作品定位】 (platform / genre / tags / audience / sellingPoint / pov / style, no word counts) first in the core; `chapterWords` is the default target length when the settings don't set 每章字数. `novel.book` = the auto-plan 全书骨架 (`planner.clean_book`, update `{book}` too).
- **Constraints** (`spec.py`): world / plot / style plain fields + the protagonist (role contains 主角) + a character roster → **core** (system message, never trimmed); other characters, plot milestones, custom elements (category overview + one card per item, keyed by names) → **retrievable cards**; missing built-in categories → "尚未设定" (open, may be invented without contradiction). `plot.chapters` / `plot.wordsPerChapter` are parameters, not facts (the latter is the default target length).
- **Layered context** (`context.py`, real tokenizer): L0 core + L4 task are mandatory (error if they exceed `window − maxNewTokens − 64`); then L3 recent text minimum (256 tokens of the chapter so far, or the previous chapter's ending), L2 latest chapter summary, L1 cards with keyword relevance > 0 (irrelevant cards are never sent), **L1b 【故事账本】** (`facts.context_text`: ≤10 open foreshadows, most recently active first; states of characters whose name occurs in title / goal / beats / recent text / last summaries; last 5 timeline events) and **【下一章预告】** (`outline.chapters[n+1]`, last segment only, "don't write ahead"), arc summary, older summaries, then L3 is extended (≤ `params.recentTokens`, 900). The final chat-template count is verified and pieces are rolled back (extended L3 → older summaries → next preview → ledger → cards → arc → latest summary → L3) until it fits. Report layer `L1b_facts`, `included/dropped.facts|nextPreview`. API models estimate CJK at 1.0 token/char.
- **Writing flow** (`novel.params`, switches in the 写作 form 「写作流程」): `planChapter` (default on) = one JSON call before writing → `chapter.plan {beats[3–6], foreshadow[], hook}` (core + ledger + previous summary + goal + next outline chapter; failure → `planError`, writes from the goal); each segment's task lists the beats and 「本段主要写第 k 个节拍」 (`prompts.beat_at` = written / target share; last segment gets the hook). `extractFacts` (default on) = the summary call becomes `_digest` (JSON `{summary, foreshadow, characters (+ goal / obstacle / relations / knows when the chapter makes them clear), timeline, clocks}`, ≤1300 tokens, the open-foreshadow list is sent so the model cites ids) → `facts.merge` + `chapter.facts` (this chapter's changes); unparsable JSON (small local models) → `factsError` + the old plain summary call, the chapter still completes. `reviewChapter` (`null` = on for 大模型, off for local) = one JSON call after the digest comparing core settings, `view_before(n)` ledger, recent summaries and the text → `chapter.review {issues[{type setting\|character\|timeline\|foreshadow\|logic, quote, found (quote occurs verbatim → UI can jump to it), detail, fix}], at, model, ignored}` / `{error}`; reports only, never edits. All three are `_json_call`s (adapter off, `GenParams.json_mode` → `response_format` for API models, lenient `_parse_json`), recorded as call types `plan` / `digest` / `review`. A hand edit of the text sets `factsStale` (UI offers 重新提取). `list_chapters` exposes `reviewIssues` (null = not checked / failed / ignored)
- **Segmented chapters** (`chapter.py`): each segment ≤ `params.segmentTokens` (768, capped at window/4) and only sees the chapter tail, never the whole chapter. Stops at ~95% of target chars, natural end on the last segment, cancel, or a segment cap. Then a summary call (≤150字, temp 0.3); when > 8 unmerged chapter summaries exist the oldest 5 are merged into `arcSummary`. Every call (type, prompt/completion tokens, finish reason, seconds, layer report) is stored on the chapter and added to the workspace totals. One generation job at a time; refused during training; model load/unload/training are refused while a chapter is generating.
- **Storage** (`store.py`): `data/novels/<id>/novel.json` (incl. `outline`) + `facts.json` (故事账本) + `chapters/NNNN.json` (`${DATA_DIR}/novels`; `NOVELS_DIR` still overrides). Python is the only writer; Java may read per `data/README.md`. All persistence goes through `store.py` so the planned MySQL migration replaces only that module.
