### Local models & style fine-tuning (`app/local/`, `/api/local/**`)

Local-only for now; remote inference/training must plug into the existing extension points (`source` on registry records, `backend` on jobs + `worker.RUNNERS[(kind, backend)]`). The frontend calls these endpoints **directly** (CORS: `CORS_ORIGINS`, default 5173/5174) — an explicit exception to "frontend → Java → Python", because model files live next to the Python service. Responses use `{code, message, data}` (code 0 = success; `LocalError` → HTTP status).

| Method & path | Purpose |
|---------------|---------|
| `GET  /api/local/system` | GPU (nvidia-smi), RAM, disk, dependency versions, inference state, active job |
| `GET  /api/local/models` · `POST /models/register {name, path}` (HF dir, **or a `.gguf` file / dir with one GGUF** → `task: gguf`, display only: `registry.inspect_gguf` reads the header — arch, `quant` from `general.file_type` or the file name, `contextLength`, `numParams` from `size_label`, shards summed; never loaded / trained, `registry.not_generation_reason` explains llama.cpp → 模型配置; deleting the record never deletes the file; HF records carry `quantMethod` from `quantization_config`) · `POST /models/download {repoId, name, source?, targetDir?}` · `POST /models/download/check {repoId, source?, targetDir?}` · `GET /fs/dirs?path=` · `GET /models/download/sources` · `POST /models/{id}/delete` | Base models. Register = record path only (no copying); download = background job into `models/base/<id>/weights/` — or `<targetDir>/<repo name>/` (absolute, not under `%SystemRoot%`, must be empty or a previous unfinished download marked by `.nan_novel_downloading`; recorded `ownsFiles`, so deleting the record deletes those files) — then auto-register. `check` = source / size / free space of the target disk (sync, network); `fs/dirs` = read-only directory browser for the 保存位置 picker (empty path = drives). 7B (≈15 GB) is in the recommended list and defaults to a custom location. `source`: `auto` (default, tries `MODEL_DOWNLOAD_AUTO_ORDER` = modelscope → hf-mirror → huggingface, falling through on failure) / `modelscope` (HTTP API, per-file size + SHA-256 check, no `modelscope` package) / `hf-mirror` / `huggingface`; HF sources are pre-checked with `config.json` metadata because a mirror that 308-redirects to huggingface.co otherwise surfaces as `LocalEntryNotFoundError`. Env: `MODEL_DOWNLOAD_SOURCE`, `MODEL_DOWNLOAD_AUTO_ORDER`, `HF_MIRROR_ENDPOINT`, `HF_ENDPOINT`, `MODELSCOPE_ENDPOINT`; legacy `useMirror` still accepted |
| `POST /api/local/estimate {baseModelId, mode: infer\|train, quantization: 4bit\|none, maxSeqLen, batchSize, loraR, adapterId?}` | Conservative VRAM/RAM estimate → `level` ok/warn/exceed + messages. `infer` accounts for the adapter's weights and for what this service already holds: same base + quantization resident → only the adapter delta (`resident: true`); another resident model → its VRAM counts as free (unloaded before loading) |
| `GET  /api/local/adapters` · `GET /adapters/{id}` · `POST /adapters/{id}/rename` · `POST /adapters/{id}/delete` | LoRA adapters (ids must match `[A-Za-z0-9][A-Za-z0-9_-]*`, never paths); each has `compat` + `matchedBaseId` (the local base it may load on). Local adapters: ok/changed/missing vs the base id + config hash; if that base record was deleted, any registered base with the same path or config bytes matches (re-registration keeps adapters usable). Loading always requires `matchedBaseId == baseId`. Remote-trained (`source: remote`): ok only when a local base has the same config (raw or `configCanonicalHash`, CRLF-safe) **and** the same official weights fingerprint (local side computed by `registry.verify_base_weights`, cached in `model.json`), else unverified/changed/remote-only |
| `GET  /api/local/embedding` · `POST /embedding/load {baseId?}` · `POST /embedding/unload` · `POST /embedding/similarity {query, texts[], baseId?}` | Embedding models (`app/local/embedding.py`): base models whose `task` is `embedding` (`registry.model_task`: bert / xlm-roberta … without a causal-LM head; old records get it from `modelType`/`architecture`). Resident independently of the generation model (fp16 on CUDA, < 200 MB); moved to CPU while a local training job holds the GPU. CLS pooling + L2 norm, bge query instruction prefix. Vector cache `data/material-index/<baseId>/` (`vectors.npy` + `keys.json` + `meta.json`, key = SHA-1 of the text, invalidated when configHash / size change). Embedding models are rejected by `inference/load` and `train`, and filtered out of every generation / training picker (`isEmbeddingModel`); 本地模型 page offers 「相似度测试」 for them |
| `GET  /api/local/reranker` · `POST /reranker/unload` · `POST /reranker/score {query, texts[], baseId?}` | Rerank models (`app/local/reranker.py`, task `reranker` = `…ForSequenceClassification`, e.g. `BAAI/bge-reranker-v2-m3` downloaded to `E:\workplace\model\`): cross-encoder over (query, text) pairs, relevance = sigmoid(logit) 0–1. Resident independently (fp16 CUDA ≈ 1.1 GB; CPU while training holds the GPU); a CUDA OOM skips reranking for that call. Like embedding models they are rejected by `inference/load` / `train` and hidden from generation pickers (`isRetrievalModel`); 本地模型 page 「相关度测试」 |
| `GET  /api/local/llama` · `POST /llama/settings {serverPath}` · `POST /llama/check {baseId? \| path?, ctx, ngl}` · `POST /llama/start {…, stopExternal?}` · `POST /llama/stop` · `GET /llama/log?lines=` | **llama.cpp (GGUF) managed by Python** (`app/local/llama.py`, page `views/ai/llama.vue`, route `/ai/llama`): one `llama-server` at a time on `LLAMA_PORT` (default 8001, test instance uses 8002), started in the background without a window (`CREATE_NO_WINDOW`, output → `models/llama/llama-server.log`), always with `--parallel 1 --cache-ram 0`. `check` = file / header (`registry.inspect_gguf`), server exe (`serverPath` saved in `models/llama/settings.json`, default `LLAMA_SERVER_PATH` or the D: build), port owner (`netstat` + `tasklist`), VRAM estimate = weights × GPU-layer share + f16 KV (`block_count` × `head_count_kv` × `key_length` × ctx) + 0.4 GB vs nvidia-smi free (+ what our running llama would free) → `level ok\|warn\|error`. `start` stops our previous llama first; a foreign `llama-server` on the port (e.g. `start-llama.bat`) → 400 `data.needConfirm`, resend with `stopExternal: true` (kills only that PID after checking it is `llama-server.exe`); any other program on the port → error. A watcher thread polls `/health` (≤300 s) and records unexpected exits; `explain_failure` maps log lines to 显存不足 / 架构不支持 / 文件损坏 / 端口被占. The process is put in a `KILL_ON_JOB_CLOSE` job object and stopped by the FastAPI shutdown hook, so it never outlives the AI service. Default = not started; `settings.last` preselects the last model on the page. Deleting a registered GGUF that is running is refused |
| `GET  /api/local/inference` · `POST /inference/load {baseId, adapterId?, quantization: auto\|4bit\|none}` · `POST /inference/unload` · `POST /inference/generate {prompt, maxNewTokens, temperature, topP, repetitionPenalty, useChatTemplate, useAdapter?, seed?}` · `POST /inference/compare {same body}` · `POST /inference/evaluate {text, maxTokens?}` | One model resident in VRAM; load is async (`idle/loading/loaded/error`). Same base + quantization already loaded → `load` only enables/disables/attaches the adapter (`switched: true`, no base reload); `attachedAdapterId` = adapter weights resident, `adapterId` = active (disabled → output inside `disable_adapter()` = pure base). `compare` = base then adapter with the same seed (needs an attached adapter). `evaluate` = mean token loss / perplexity of the same text with the adapter off vs on (`lossDelta`, `pplChangePct`; 本地模型 page「困惑度评估」) |
| `POST /api/local/train` (`TrainReq` in `router.py`) · `GET /jobs` · `GET /jobs/{id}` · `GET /jobs/{id}/log?lines=` · `POST /jobs/{id}/cancel` | Fine-tuning jobs; 409 + estimate when resources would be exceeded (resend with `force: true`) |

- **Model kinds** (frontend `api/localModel.js#MODEL_KINDS` / `modelKind`): 生成模型 (`causal-lm`) / 向量模型 / 重排模型 / GGUF · llama.cpp. The 本地模型 page shows a dark kind tag + capability tags per row (可直接运行, 适配器 N 个 / 可加适配器, 可 QLoRA 微调 ≤ 3.5B or 仅推理, 已量化 · GPTQ…, 无对话模板; GGUF: quant, 上下文, 「使用方法」 dialog with the `llama-server` command and a link to `/ai/model?llamacpp=1&name=&model=` which opens a prefilled config form). **Every generation-model picker filters with `isGenerationModel`** (not `!isRetrievalModel`) so GGUF never shows up there.
- **Storage** (`app/local/settings.py`, override root with `LOCAL_MODELS_DIR`): `models/base/<id>/model.json` (path, modelType, arch, numParams, sizeBytes, `configHash`), `models/adapters/<id>/` (PEFT files + tokenizer + `meta.json`: exact base model fingerprint, training config, dataset stats, metrics, post-training sample), `models/jobs/<id>/` (`job.json`, `progress.json`, `job.log`, `samples.txt`, `cancel` flag). Adapters are written to `<id>.partial` and renamed only on success.
- **Jobs** run as separate subprocesses (`python -m app.local.worker <jobId>`) so the API stays responsive and VRAM/RAM are released when they end. One job at a time; starting training unloads the inference model and loading is refused while training. On Windows never probe PIDs with `os.kill(pid, 0)` (it kills the process) — use `jobs.pid_alive`.
- **Training** (`training.py`): samples (pasted text and/or Java file ids via `text_loader`) are packed into `maxSeqLen` blocks for causal-LM continued training; PEFT LoRA on `all-linear`, gradient checkpointing, cosine LR, `paged_adamw_8bit` for QLoRA (nf4 + double quant, bf16 compute on RTX 40xx). Cancel = flag checked every step (force-kill after 90 s).
- **Hardware assumptions** (dev machine): RTX 4060 Laptop 8 GB (≈6.3 GB free with the display), 16 GB RAM (often only ~2 GB free), C: nearly full. Defaults are conservative (`maxSeqLen` 512, batch 1, grad-accum 4, r 16). 0.5B–1.5B (3B borderline) are the intended QLoRA sizes; 7B QLoRA is reported as *exceed*. GGUF files cannot be trained.
- **Install**: torch's CUDA wheel is not on PyPI — see the header of `requirements-local.txt` (Aliyun mirror / resumable download). The extraction service still runs without these packages; torch is imported lazily.
- **E2E test**: `.venv/Scripts/python scripts/local_e2e.py --model-path <HF model dir> --port 8011 [--samples my.txt]`.
- **Adapter effect check** (no training): `.venv/Scripts/python scripts/adapter_eval.py --adapter <id> --port 8011 [--model-path <base dir to register if none matches>] [--style-file x.txt] [--control-file y.txt] [--skip-novel]` → perplexity base vs adapter on style text (default: middle of the training job's `samples.txt`, i.e. in-sample) and a built-in unrelated control text, same-seed continuations, then a temporary workspace generating one short chapter with the adapter. Exit 0 = style loss drops > 0.05 and more than on the control.
