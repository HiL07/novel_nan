# 跨世界观角色卡

把一个人物（真实人物传记、小说角色）的**内核**提取成「原型卡」，再放进另一个世界观生成「适配版本」，写进小说工作区后参与章节规划、写作和一致性检查。

代码：Python `python-service/app/persona.py`（提取 / 适配 / 检查 / 试聊 / 辨识度测试，全部模型调用）、
Java `PersonaService` + `PersonaController`（存储、版本、出处规则、任务状态）、前端 `views/persona/index.vue` + `components/persona/*`。

## 1. 原型卡的结构

| 字段 | 说明 |
|---|---|
| `traits[]` | `{id t<n>, layer, text, kind core\|adaptable, locked, provenance quoted\|inferred\|user, confidence high\|medium\|low, evidence[{id, quote, observation}], editedBy ai\|user, aiText}` |
| `rules[]` | 行为规则 `{id r<n>, situation, reaction, reasoning, traitRefs[], provenance, evidence}`，必须覆盖 6 类情境：面对未知现象 / 与自身理论矛盾的证据 / 权威压制 / 失败 / 危险 / 利益冲突 |
| `expertise` | `knowledge / methods / intuition / logic` + `worldBound[]`（只属于原世界的术语，适配后不能出现） |
| `voice` | `style / argumentation / tendencies / emotion`；`lines[]` = 核实过的原话 |
| `arc` | `formative[{experience, change}] / growth / fall` |
| `signature` | `mustKeep[]`（特征 id，少了就不是他）/ `easyToLose[]` |
| `memories[]` | 经历记忆 `{scene, situation, thought, action}`，试聊时按话题检索 |
| `uncertain[]` | 需要作者判断的点（只有形容词没有规则的特征、缺的情境、低置信度…） |
| `holdout[]` | 留出的 20% 证据（≥10 条时），**不参与生成**，只给辨识度测试的评委当参照 |
| `coreConfirmed` | 作者确认了核心 / 可变之后才能生成适配版本 |

层次 `layer`：thinking 思维方式 / values 价值观 / motivation 动机 / fear 恐惧 / personality 性格 / behavior 行为习惯 / voice 说话方式 / relationship 人际关系。

## 2. 提取

1. **定位**：`whole`（整篇都关于他，或资料 ≤ 30000 字）→ 全文切块；否则在名字 / 别名每次出现处前后各取 800 字（`WINDOW`），重叠的窗口合并，再拼成约 3000 字（`chunkChars`）的块。
   块数超过 `maxBlocks`（默认 60）时**分层抽样**：开头 / 中段 / 结尾三段各取三分之一，保证人物早期和后期都被读到（人物会成长）。
2. **逐块记笔记**（一块一次调用）：只记录这段文字说明了这个人什么，每条必须带 `quote`。引文用素材流程的 `material_facts.Source.locate`
   在本块里核对（规范化子串或 ≥60% 字符三元组重合），对不上的丢弃并计数（`stats.dropped`）。实体档案「提取为原型」时，档案里已核实的事实作为种子证据加入。
3. **去重**、**留出** 20% 证据给评委（按名字的哈希固定随机，重跑结果一致），其余编号 E1…En。
4. **汇总**（一次调用）：模型写特征 / 规则 / 专业 / 说话方式 / 弧线 / 辨识度 / 记忆，引用证据编号。
5. **代码判定出处**（`build_prototype`）：引用了真实存在的证据 → `quoted`，置信度按证据数（≥3 高、2 中、1 低）；没有证据或引用不存在的编号 → `inferred` + 低置信度。
   模型自己写的 provenance 一律忽略。规则的 `traits` 序号映射成特征 id。

断点：`data/extract-cache/p<cardId>/`（阶段 `notes` 每块一行、`synth`），指纹 = 名字、别名、whole、字数、文件、块数、块大小。停止 / 重启 / AI 服务挂掉后「继续」不重读已完成的块。

## 3. 版本（只追加）

`persona_card_version` 每次保存插入一行，`persona_card.current_version` 指向最新；旧版本从不修改，「恢复」= 把旧版本另存为新版本。
保存时 Java 和上一版本逐条比较（`PersonaService.markEdited`）：

- 文字改过 → `provenance: user`、`editedBy: user`，第一次改时把 AI 原文存进 `aiText`；
- 没改 → 出处和证据**以上一版本为准**（前端传什么都不算，防止把推断改成「原文」）；
- 新增的 → 一律 `user`，去掉证据。

## 4. 适配

输入：原型（指定版本，默认当前）+ 目标世界观（某个工作区的设定 = 书名 + 核心设定 + 设定卡片，≤6000 字；或手写）+ 作者期望。
一次调用，模型输出 `coreManifest`（每条核心特征在新世界里怎么体现）、`adaptedTraits`、`expertiseMap`、`rules`、`voice`、`forbidden`、`unknowns`、`examples`、`memories`、`card`。

代码保证（`build_adaptation`）：

- 核心 / 锁定特征的**原文由代码复制**，模型只能写 `inWorld`；模型对核心特征的 `adaptedTraits` 被丢掉；
- `unknowns` 自动并入原型的 `worldBound`；
- `checks`（`check_adaptation`）：`missingManifest`（没写体现的核心特征）、`changedLocked`（锁定特征文字和原型不同）、
  `leaks`（适配内容里出现了 `worldBound` / `unknowns` 里的词）、`missingSituations`；`ok` = 前三项都为空；
- `brief`（`render_brief`）= 写作时给模型看的【人物内核·名字】文字块，由代码拼，不让模型自由发挥。

作者编辑后保存 → Python `/api/persona/adaptation/check` 重新检查、重新拼 brief（不调模型），状态回到草稿。只有**确认**过的适配版本能用于工作区。
原型出了新版本时适配版本标 `prototypeUpdated`。

## 5. 写进工作区与写作

「用于工作区」把适配版本的快照（`name, aliases, identity, core, rules, voice, forbidden, unknowns, examples, memories, brief, adaptationId, version, role`）
写进 Python 的 `novel.personas`（`POST /api/gen/novels/{id}/personas`，整体替换；同一适配版本或同名人物替换旧快照）。生成时不依赖 Java。

- `spec.build_for(novel)` = 设定约束 + `apply_personas`：定位含「主角」的人物 brief 进**核心设定**（system，不会被裁掉）；
  其他人变成检索卡片 `persona.<名字>`，关键词 = 名字 + 别名，`context.build` 里相关的人物内核卡**排在普通卡片前面**（预算紧时后裁）。
- 规划 `_plan`：本章涉及的人物（标题 / 目标 / 前情 / 下一章预告里出现名字）的**决策规则**（`rules_text`）放进规划提示词，并要求「违背内核要写出原因」；放不下时在 core 之前裁。
- 一致性检查 `_review`：同样附上决策规则，新增问题类型 `persona`（人物内核不符）；另外代码用 `scan_unknowns` 扫正文：
  某人物在场（名字出现）且正文出现他「不知道」的词 → 追加一条 `persona` 问题（`found: true`，可点击定位），模型漏报时也能抓到。
- AI 构思 / AI 填写（`ideas._context`）也用 `build_for`，所以人物内核会出现在构思上下文里。

快照不会自动更新：角色卡库里改了适配版本后，`GET /api/persona/novels/{id}` 的 `outdated` 为真，需要重新「用于工作区」。

## 6. 辨识度测试

目的：验证适配版本**真的像原型**，而不是只是一个同名的普通角色。

1. 出题（演员模型）：6 个对应六类情境的场景 + 2 个「诱导场景」（需要用到他不该知道的知识）。
2. A = 适配版本（完整 brief，试聊同款 system），B = 对照：只有名字、身份、一句话和世界设定。两边各演一遍。
3. 评委（可单独选一个大模型配置）看到的两份反应**去掉名字、随机交换顺序**；按**扣分制**：逐条列缺陷，严重度 1–5、每级扣 4 分，从 100 扣；
   长度校正 + min(10, 字数/100)（越长越容易被挑出毛病）；逐条判断核心特征 体现 / 未体现 / 违背；选出更像原型的一份。评委参照里有留出的 holdout 证据。
4. 保护性：A 的回复里出现 `unknowns` 的词 = 泄漏（代码判定）。
5. 心理访谈：6 个问题（`INTERVIEW`），原型在原世界回答一遍、适配版回答一遍，评委逐题判断价值观 / 恐惧 / 选择倾向是否一致（忽略世界背景）。
6. 一致性复测：前 2 个场景让 A 再演一次，评委判断两次决策是否一致。

`summary`：`scoreA / scoreB`（平均分）、`pickedA`（评委选中 A 的比例）、`manifestA / manifestB`（核心特征体现率）、`violationsA`、`leaks`、`interviewAgreement`、`consistency`。
报告存在 `persona_adaptation.tests`（最近 10 次）。

### 实测（2026-10-29，DeepSeek deepseek-chat）

拉瓦锡传记约 900 字（`whole`），目标世界「玄炉界」（修仙，丹方被宗门垄断，没有度量衡）：

- 提取 21 s：9 条特征（全部 `quoted`）、7 条规则，核实 11 条证据、丢弃 0 条，留出 2 条，5 条「需要作者判断」。
- 适配 19 s：「安衡」，外门丹房杂役；检查通过（缺 3 类情境的规则，不影响 ok）；`unknowns` 12 个（氧气、燃素说、天平、断头台…）。
- 辨识度测试 90 s、28 次调用、21.5k 输入 + 7.4k 输出 token（约 0.1 元）：**A 75.3 分 vs 对照 B 43.7 分**，评委 6/6 选中 A，
  核心体现率 A 72% / B 28%，违背 1 次，泄漏 0（两个诱导场景都没说出「氧气」「燃素」），访谈一致 100%，复测一致 100%。
- 观察：B 也会「称量」——场景本身由演员模型按适配版本出，已经暗示了测量；差距主要在 B 会顺从 / 冲动，A 按规则处理权威与危险。
  同一个模型既演又评有偏差，正式比较建议评委选另一个模型。

假模型端到端（端口 8098）也完整跑通：A 96 / B 80、选中 A 100%（假模型的分数只说明流程通了）。

## 7. 存储

SQLite（`sql/persona.sql`，也在 `init.sql`）：`persona_card`（元数据 + 提取任务状态，`options` 存提取参数和粘贴的原文，不含密钥）、
`persona_card_version`（`content` JSON，`UNIQUE(card_id, version_no)`）、`persona_adaptation`（`content` / `applied` / `tests` JSON + 测试状态）、`persona_chat`（见 [试聊](试聊.md)）。
单张卡几十 KB，放在数据库里；人物资料原文不另存文件（粘贴的文本 ≤60 万字存在 `options` 里，文件来源只存 file id）。
