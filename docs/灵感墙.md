# 灵感墙

素材库里的素材已经核对过原文、可以合并成多个版本、可以按版本检索，但以前只能**被动挑选**：作者先想好要什么，再去库里找。
灵感墙反过来：作者只给一个念头（「主角去冒险」，可以加「北方冰原」），甚至什么都不给，AI 就主动从素材库里找出地点、魔物、物品、势力、剧情骨架，
组合成几个具体的思路，并标明每处借了哪条素材、改了什么。作者可以收藏、细化、追问修改，再写进工作区。

代码：Python `python-service/app/generation/inspire.py`（`/api/gen/inspire/plan|ideas|refine|revise`）；
Java `InspirationService` / `InspirationController`（`/api/inspire/**`）；前端 `views/inspire/index.vue`、`components/inspire/`（`IdeaCard`、`ApplyDialog`）、`api/inspire.js`。

## 墙

- 可以建多面墙，比如「西幻法师冒险」「都市悬疑」。每面墙可以**关联一个工作区**。关联后，每一步构思都会带上这本书的设定（核心 + 卡片）、
  已采用的大纲和最近章节（复用 `ideas._context`），思路也可以「写进工作区」。
- 墙上放两种东西：**收藏的思路**和**钉上去的素材**。
  - 钉的素材每次检索都排在最前（`from = wall`）。
  - 收藏的思路取最近 12 条的标题和卖点，作为【灵感墙上已收藏的思路】交给模型，要求新的思路不重复，也可以在它们的基础上延展。
- 每面墙有自己的「屏蔽来源书」（`exclude_books`），检索和逛素材都会遵守；被「保留」的素材照常可用，和素材库的规则一致。

## 三步流水线

| 步骤 | 谁做 | 花不花 token | 输出 |
|---|---|---|---|
| ① 拆需求 | 模型，1 次调用（≤900 tokens，温度 0.6） | 花 | `{summary, needs[{category, query, count 1–6, why}] ≤8 条, explore}` |
| ② 检索素材 | Java + 本地检索 | 不花 | 按需求分组的候选素材，总数 ≤24 |
| ③ 生成思路 | 模型，1 次调用 | 花 | N 个思路（默认 3，最多 5） |

两种跑法共用这三步：
- **一键出思路**：前端依次调用三步，逐步显示结果；
- **先看素材**：第 ② 步之后停下，作者可以改需求（分类 / 检索词 / 条数，增删）、勾掉素材、给多版本素材选用法、从素材库手动加，然后再生成。

### ① 拆需求

- 有需求或条件时，模型按需求判断要找哪些素材。补充条件里的地理环境和限制必须写进相关需求的检索词。
- 没写需求，但关联了工作区：模型根据这本书的设定、大纲和最近章节，判断接下来最需要什么。
- 什么都没给，也没有关联工作区：模型按「生成什么」列出宽泛、多样的检索方向，同时**开启随机探索**。
  - `explore` 由代码决定，不由模型决定；作者也可以在界面上手动打开或关闭。
- 代码检查：分类不在固定的 7 类里、或者检索词为空的需求丢掉；`count` 限制在 1–6；一条可用的都没有就报错。

### ② 检索素材（本地）

1. 钉在墙上的素材排在最前（已合并进主条目的成员跳过）。
2. 每条需求调用 `MaterialService.vectorSearch(query, category, excludeBooks, limit = count × 4)`，
   也就是向量 + BM25 混合召回，再用交叉编码器重排（见 [素材检索](素材检索.md)）。
   - 重排过：只取相关度 ≥ `RERANK_MIN_SCORE`（30）的；
   - 没有重排模型：取前 3 条（`UNRANKED_TAKE`），因为余弦分数只有相对意义。
   - 同一条需求里，**每本书最多 2 条**（`PER_BOOK`），避免一本书的素材占满一组。
   - 已经出现在前面分组里的素材不重复出现。
3. **多版本素材**：检索命中某个版本（`matchedVariant`）就默认「只用这一版」，否则默认「让 AI 选」。作者可以改成融合或别的版本。
4. **随机探索**（`explore`）：在需求涉及的分类里（没有需求时用除「情节」外的全部分类），每类随机抽 2 条。
   - 抽法：SQL `ORDER BY RANDOM()` 先取一批（≥40 条）；内容充实的（概括 + 详细 ≥60 字）排前面，同档内保持随机；
   - 每本书最多 2 条，跳过已经选中的素材。
   - 目的是给出「没想到可以这样组合」的东西。
5. 总数上限 24 条（`MAX_MATERIALS`）：超出时从靠后的分组裁掉，所以钉的素材和前面的需求优先保留。

### ③ 生成思路

- 素材条目由 `NovelGenService.materialItems` 组装，和 AI 构思 / AI 填写用的是同一份。
  - 内容：分类、标题、概括（+ 详细 ≤300 字）、属性、标签、来源书；
  - 合并主条目会附上各版本和用法（auto / blend / fixed），写法沿用 `ideas._material_lines`，见 [精炼合并](精炼合并.md)。
- 在提示词里，每条素材编号为 `[S1]（来自《书名》） [分类] 标题：内容`。
- 要求：
  - 生成 N 个彼此差异明显的思路；
  - 每个思路至少借用 2 条素材，再加至少一处素材里没有的**反转**；
  - 不同思路尽量用不同的素材；
  - 借用时改名、改细节，不照搬原作；
  - 补充条件必须满足。
- 思路的结构按「生成什么」决定（`TARGET_SHAPE`），例如「冒险路线」= 3–6 站，每站写清地点 → 遭遇 → 事件 / 转折。
- 每个思路包含：
  - `title`、`pitch`（一句话卖点）；
  - `sections[{heading, text, sources}]`；
  - `elements[{category, name, desc, sources, change}]`：新名字、在这个构思里是什么、相对素材改了什么；
  - `twist`、`questions`（1–3 个待作者决定的问题）。
- **引用检查（代码）**：
  - `sources` 里的 `S 编号` 换成素材 id；不在本次素材里的编号直接去掉，所以模型编造的引用不会出现；
  - 一条有效引用都没有的思路标 `uncited`，界面上显示「未引用素材」，卡片边框变黄；
  - Java 再把 id 换成 `sourceRefs[{materialId, title, book, category, variant}]`，供界面展示。
- token 上限：
  - 大模型：每个思路 1100，再加 400；
  - 本地模型：每个思路 700，再加 400；
  - 输出被截断（`finishReason = length`）时报错，提示减少思路数，不保存半截结果。
- 每次生成存一条**构思记录**（`inspiration_run`），包括请求、需求拆解、所用素材、思路和用量。之后的细化 / 修改会写回这条记录。

## 四个出口

| 出口 | 做法 |
|---|---|
| 收藏到墙 | 思路连同 `sourceRefs` 复制成墙上的一条 `idea`；之后在墙上细化 / 修改，直接改这一条 |
| 细化 | 用同一组素材，把思路写成 800–1500 字、3–8 段的详细内容，可以附一句要求（「重点写第 3 站」）。结果放在思路的 `detail` 里，不覆盖原思路 |
| 追问 / 改 | 用一句话指令修改，只改指令涉及的部分。可以先把某条素材划掉，或换上别的素材，界面会把它们拼进指令。之前的指令作为【之前的修改要求】一起发给模型；每次修改前的版本存进 `history`，可以「退回上一版」 |
| 写进工作区 | 墙关联了工作区时可用，三种写法见下 |

写进工作区（`ApplyDialog`）有三种写法：
1. **追加为大纲章节**：思路的每一段（细化过就用细化后的段落）变成一章，编号接在大纲和已写章节的最大章号之后。
   - 先预览，可以改标题、改目标、删章；确认后前端直接调 Python 的 `novels/{id}/update {outline}` 保存。
   - 写作页会按大纲自动填入下一章的标题和目标。
2. **加进设定**：勾选思路里的元素，跳转到工作区。
   - 元素被当作「没有 id 的素材」交给设定编辑器的 `applyExternal`，走同一套 `materialApply.applyMaterial`：怪物 / 地点 / 势力 / 物品进对应列表，世界观追加到补充说明；
   - 因为没有素材 id，不会标「来自素材库」，也不会计入素材使用次数；
   - 加完要作者自己「保存设定」。
3. **填进构思方向**：把标题、卖点、各段和反转拼成文字（≤3000 字），替换工作区「AI 构思」页的构思方向框，之后可以接着生成大纲或后续走向。

2 和 3 需要工作区页面上的编辑器，所以经 `sessionStorage`（`nan_novel.inspire.apply`，读完就删，10 分钟内有效）交给工作区页面处理。

## 逛素材

不花 token。按分类（或全部）跨书随机抽 12 条，每本书最多 2 条，抽法同随机探索。可以「换一批」，也可以把素材钉到墙上。
用来在没有明确想法时，先看看库里有什么。

## 模型

拆需求、生成、细化、修改都可以用大模型、GGUF（llama.cpp）或应用内本地模型，界面上选，并记在 localStorage `nan_novel.inspire.model`。
模型的解析由 Java 的 `NovelExtractService.resolveModel` 完成：大模型 key 只在这次请求里，不写进记录。
小模型一次写多个思路时 JSON 格式不太稳定：解析沿用 `ideas._parse` 的宽松规则，界面也会提示换大模型。用 DeepSeek 构思一次大约几分钱。

## 测试

- 离线：`_clean_idea` 的引用换算、无效编号去掉、`uncited` 标记，以及需求的分类校验和 `count` 截断。
- 端到端（测试端口 8011 / 8012，假模型 8099，临时数据目录）：
  - 拆需求的提示词带上工作区和补充条件；
  - 钉的素材排第一，钉两次只算一次；
  - 检索结果跨组不重复，每组每本书 ≤2 条，屏蔽书生效；
  - 去掉一条素材后，它不会出现在生成的提示词里；
  - 思路的 `sources` 是素材 id，无效引用的思路被标 `uncited`；
  - 收藏后墙的计数正确；
  - 细化带上要求，修改带上历史；
  - 构思记录能更新；
  - 收藏的思路会进下一次拆需求的提示词，空需求也能跑；
  - 逛素材每本书 ≤2 条，无效分类返回 400；
  - 大纲能追加；取消关联、删条目、删墙都正常，删墙不影响素材。
