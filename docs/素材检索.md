# 素材检索：向量 + 关键词混合召回、重排、多版本召回

> 相关代码：Java `MaterialService.vectorSearch / search / vectorText / variantText`、`NovelGenService.ideas`（自动匹配）；
> Python `app/local/embedding.py`（向量、融合）、`app/local/lexical.py`（BM25）、`app/local/reranker.py`（重排）。
> 全程在本机运行，不调用大模型、不花 token。

## 1. 整体流程

```
查询 ──┬─► 向量召回：bge-small-zh-v1.5 余弦相似度，前 50 ─┐
       │                                                    ├─► 倒数排名融合（RRF, k=60）─► 前 30 条 ─► 重排（bge-reranker-v2-m3）─► 结果
       └─► 关键词召回：BM25（jieba 分词），前 50 ──────────┘
```

Java 负责过滤（分类、标签、屏蔽的来源书、已合并的成员），把候选素材的检索文本交给 Python（一次最多 20000 条，
不做关键词初筛），Python 召回、融合、重排后返回。

## 2. 检索文本：写什么、不写什么

每条素材的检索文本 = 名称 / 细分类型 / 标签 / 概括 / 属性**值**，只拼有内容的部分（`vectorText`）。

**不写分类名和属性键名**：「怪物」「外形」「弱点及原因」这些词每条同类素材都有，写进去会把所有向量互相拉近，
相似度分不开。分类本来就是过滤条件，不需要靠向量区分。

素材都在 512 token 以内，不切块。

## 3. 向量召回

- 模型：`BAAI/bge-small-zh-v1.5`（GPU 上 fp16，不到 200 MB 显存；本地训练占用 GPU 时自动挪到 CPU）。CLS 池化 + L2 归一化，内积即余弦相似度。
- 查询前缀：bge 中文模型对查询加「为这个句子生成表示以用于检索相关文章：」，素材文本不加（bge 官方用法）。
- 缓存：`data/material-index/<模型 id>/`，按文本的 SHA-1 存向量。素材改了，文本变了，下次检索时自动重新编码。模型的配置或大小变了，整个缓存作废。

## 4. 关键词召回（BM25）

- jieba 分词；把素材库里所有标签和一批网文常用词（退婚、扮猪吃虎、金手指……）加进词表，避免被切碎。
- 去掉停用词；BM25 参数 k1 = 1.5、b = 0.75。
- 作用：补上向量模型对专有名词、生僻设定词不敏感的问题。

## 5. 融合与重排

- **倒数排名融合（RRF）**：每条素材的融合分 = Σ 1 / (60 + 它在各路召回里的名次)。只用名次、不用原始分数，所以两路分数的量纲不同也没关系。
- **重排**：融合后的前 30 条交给交叉编码器 `BAAI/bge-reranker-v2-m3`，逐对读（查询，素材），相关度 = sigmoid(logit)，范围 0–1。
- **分数的含义**（界面上显示 0–100）：
  - 重排过：相关度 × 100，可以当绝对阈值用，**≥30 约等于「相关」**（`RERANK_MIN_SCORE`）；
  - 没重排（没装重排模型、显存不够）：余弦相似度 × 100，只能看相对高低。此时按融合顺序返回，结果标 `reranked: false` 并说明原因。

## 6. 合并主条目的多版本召回

精炼合并后，同一个主条目下可能有写法差别很大的几个版本，比如「神水」：①宗教圣物（增加勇气）/ ②狂信药剂（让人成为狂信徒）。

**不把各版本拼成一条向量。** 拼起来的向量会落在两种写法中间，搜哪一种都不如原来准。做法是按版本分别召回，结果以主条目返回：

```
「神水」主条目在检索池里展开成多条检索文本：
  共性                主条目自己的检索文本
  ① 宗教圣物          主条目名称 + 版本名 + 独有设定 + 成员原文
  ② 狂信药剂          同上
        │  照常：向量 + BM25 召回 → 融合 → 重排
        ▼
命中任一版本 → 返回主条目，同一主条目只出现一次（结果已按分数排序，留第一次出现的 = 各版本里分数最高的）
             → 附带 matchedVariant（命中的成员 id）、matchedLabel（版本名）
```

- 版本的检索文本里带上主条目名称，所以搜「神水」时每个版本都能被召回。
- 成员 id 本身唯一，直接当检索 id 用；向 Python 要 `limit × 2` 条，保证去重后结果够数。
- 实测（测试库）：「让人丧失自我变成狂信徒的药」→ 神水，命中 ② 狂信药剂；「能让人鼓起勇气的圣物」→ 神水，命中 ① 宗教圣物。
- **关键词检索**同理：关键词命中了已合并的成员，就返回它的主条目。另外，合并时版本名会自动加进主条目的标签。
- 已合并的成员不会作为独立结果出现，只能通过主条目找到。

## 7. AI 自动匹配素材

AI 构思 / AI 填写里的「自动匹配」用的就是上面的本地检索（混合 + 重排），取用规则：

- 重排过：相关度 ≥30 的才用；
- 没重排：分数不可比，只取最相关的前 3 条；
- 命中了多版本主条目的某个版本：这条素材按「只用这个版本」交给模型（见 [精炼合并 · AI 怎么用](精炼合并.md#6-ai-怎么用多版本素材)）；只命中共性那一条时按「让 AI 选」。

素材选择弹窗里的「向量检索」也一样：多版本素材显示「命中：② 狂信药剂」，并默认选中这个版本。

## 8. 检索反馈

向量检索后，用户勾了哪些、没勾哪些、点开看了哪些，会记到 `data/material-index/feedback.jsonl`（查询、展示的 id、选中的 id、在哪用的），
留作以后微调向量模型的训练数据。
