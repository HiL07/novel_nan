# 项目接手与核心目标

记录日期：2026-11-15。用途：保存用户意图和接手分析，供后续开发持续查阅。

## 1. 用户明确的目标

本项目此前主要由 Claude 辅助开发，现由 Codex 接手，在现有实现上继续建设。

用户本次明确：**这是一个生成小说的项目，最核心的是从其他小说提取素材，并在生成自己的小说时导入、使用这些素材。**

后续功能取舍应围绕这条链路判断：

```text
其他小说 → 提取有依据的素材 → 整理、选择、入库
        → 为目标小说选择合适的素材 → 导入创作上下文 → 生成小说
```

本次任务是记录和分析，没有确定具体改造方案，也没有要求立即修改业务代码。

## 2. 对核心目标的理解（接手判断）

- 提取的价值最终要体现在创作结果上；素材数量、检索分数只能说明链路中的部分表现。
- “导入”需要进一步明确：参考一次、转化为作品设定、用于剧情规划、指导章节写法，是不同的使用方式。
- 原书事实、可借用的机制、目标作品中实际采用的设定，应保留区分，方便核对和后续修改。
- 应能够说明“选了哪条素材、借用了什么、进入哪个创作环节”。仅有来源编号还不能证明内容真正发挥作用。

以上是基于用户目标形成的分析，不能当作用户已批准的数据结构或产品设计。

## 4. 主要问题与分析边界

1. **素材使用链路需要优先核实。** 灵感阶段有素材，不代表后续设定、骨架和正文持续保留了素材信息；文字间接继承与结构化传递应分别检查。
2. **检索相关不等于创作有用。** 现有检索评测偏向从描述找回已知素材，不能直接证明某个故事方向能找到值得采用的机制或情节。
3. **素材应按创作用途分析。** 世界规则、人物动机、剧情结构、节奏写法对输入信息和使用阶段的要求不同，不能假定一种提示词适合全部素材。
4. **引用与实际使用应分开验证。** 模型输出了素材编号，只能证明格式或编号有效；仍需查看生成内容是否保留了所选机制及其限制。
