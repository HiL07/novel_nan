# 精炼合并：共性 + 可选版本

> 相关代码：Python `app/material_merge.py`（找相似组、合并稿）、`app/generation/ideas.py#_material_lines`（交给 AI 的写法）；
> Java `MaterialMergeService`、`MaterialService`（检索、`merged_into`）、`NovelGenService`（`materialVariants`）；
> 前端 `components/material/MergePanel.vue`、`MaterialEditor.vue`、`MaterialPicker.vue`、`novel-options/materialApply.js`。

## 1. 要解决的问题

素材从多本小说里提取出来后，会出现两类重复：

- **跨书的同一种东西**：几本书都写了「狼人」，或者都有叫「神水」的东西；
- **同一本书里几乎重复的条目**：比如「银器防御规则」和「银器伤害规则」。

跨书的情况，**不同的写法恰恰是借鉴的价值所在**。所以合并不是去重、只留一条，而是：

```
神水                                         ← 主条目：只写共性
  ① 宗教圣物《耐瑟瑞尔的辉煌》：信徒饮用后增加勇气，驱散恐惧       ← 可选版本（成员素材原样保留）
  ② 狂信药剂《地狱公寓》：饮者丧失自我，成为狂信徒
```

## 2. 流程（每一步都由用户确认）

1. **查找相似素材**：本地向量模型，不花 token → 合并建议（`material_merge` 表，状态 FOUND）；
2. **AI 写合并稿**（可选）：大模型或 GGUF，一组一次调用 → DRAFTED；
3. **确认合并**：可以改主条目、改版本名和独有设定、去掉不该合的成员 → APPLIED；
4. 随时可以**拆分**还原。也可以**忽略**一组，以后查找不再建议同一组成员。

## 3. 怎么找相似素材

只在**同一分类**内比较。默认比较除情节外的全部分类，可以按来源书限定，也可以只找跨书的。

### 两两分数

```
内容相似度 c = 检索文本向量的余弦相似度
名称相似度 t = 名称向量的余弦相似度

分数 = c                         一般情况
     = max(c, (c + t) / 2)       名称很像时（t ≥ 0.85）
     + 0.08                      规范化后的名称相同，或一个包含另一个（≥2 个字）
```

为什么要看名称：不同小说写同一种东西，内容差别大、名称几乎一样。实测两本书写法不同的「狼人」，内容相似度只有 0.72，
按 0.82 的门槛会漏掉；加上名称后分数为 0.94。「狼人族」和「狼人」在门槛 0.80 时会并进来，「吸血鬼」不会。

### 聚成组

- 分数 ≥ 门槛（默认 **0.82**，可调 0.75–0.95）的两两配对，按分数从高到低贪心合并；
- 一组最多 6 条（可调 2–12）；
- 防止接龙：新成员和组里**每一条**的分数都要 ≥ 门槛 − 0.08，否则不加入（防止 A 像 B、B 像 C，串成一大串）；
- 最多返回 500 组；跨书的、平均分数高的排在前面。
- 已经写过合并稿、已合并、已忽略的同一组成员，再次查找时不重复建议。

## 4. AI 合并稿

一组一次调用。告诉模型：要合并成一个主条目，共性写在主条目里，每条原来的写法保留为一个「可选版本」；
同名但设定不同的也可以合并，作为不同版本；毫不相干的不要放进来。输出：

```json
{"same": [1, 2],
 "title": "神水", "subtype": "",
 "summary": "有 2 种写法——①宗教圣物：饮用后增加勇气、驱散恐惧；②狂信药剂：饮者丧失自我、成为狂信徒",
 "detail": "（只写共有的设定，可以为空）", "attributes": {}, "tags": ["圣物", "药剂"],
 "variants": {"1": {"label": "宗教圣物", "note": "信徒饮用后会增加勇气，驱散恐惧"},
              "2": {"label": "狂信药剂", "note": "饮者会丧失自我，成为狂信徒"}}}
```

### 依据检查（代码做）

4B 的本地模型会往主条目里填素材里根本没有的东西，比如「外形：人类与狼的混合特征」「能力：敏捷与力量」。
所以模型给的内容都要用字符二元组和原文比对：

| 内容 | 比对对象 | 不通过时 |
|---|---|---|
| 主条目的属性值、详细描述的每一句 | **至少两条成员**各自的原文，每条都要 ≥40% 二元组重合 | 丢掉（属性名记进 `droppedAttributes`） |
| 版本的独有设定 `note` | 这一条成员自己的原文，≥40% | 清空，界面上改为显示这条成员的概括 |
| 版本名 `label` | 这一条成员自己的原文，至少有一个二元组相同 | 不用，显示为「版本 N」 |

「至少两条成员」的意思是：只有一条成员写到的，是那个版本的设定，应该留在版本里，不能写进共性。
否则「只用 ② 版」时，会通过主条目把 ① 版的设定带进去。

实测：神水的合并稿里，模型把「作用：驱散恐惧」「获取方式：教会祝福」（只有 ① 有）和「代价：丧失自我」（只有 ② 有）写进了共性，三项都被这条规则挡下，各自留在自己的版本里。

这个检查只看字面重合，偶尔会把有依据但换了说法的内容也丢掉，合并时可以手动补上。

## 5. 合并后的数据

- 新建一条**主条目**素材：
  - `source = {type: "merge", mergeId, members: [成员 id], books: [来源书], variants: [{id, book, title, label, note}]}`；
  - 名称、概括用合并稿（或用户改过的）。详细、属性只放共性，**不拿某条成员的来充数**；细分类型也不沿用成员的；
  - 版本名自动加进标签，这样关键词检索能搜到「狂信药剂」；
  - 所有成员来自同一本书时，主条目也属于这本书（按书删除 / 屏蔽对它生效）；跨书时不属于任何一本。
- **成员素材原样保留**，只是 `merged_into` 指向主条目，不再出现在列表、分类计数、检索和 AI 选素材里，只在主条目的「可选版本」里展开看。
- **拆分**（或直接删除主条目）：删掉主条目，成员的 `merged_into` 清空、回到素材库，这组建议回到「已有合并稿 / 待处理」。

## 6. AI 怎么用多版本素材

用户在素材选择框里选中一个多版本素材时，可以决定怎么用它，默认是「让 AI 选」：

| 用法 | 交给模型的内容 | 提示词里的要求 |
|---|---|---|
| 让 AI 选 | 共性 + 全部版本 | 这是同一素材的不同写法：从中选一个最贴合当前设定的版本使用，不要把不同版本的设定混在一起 |
| 只用某一版 | 选定的那一个版本；主条目的概括如果在列举各版本就不带，标签也不带 | 作者选定了这个版本，按它来用 |
| 融合 | 共性 + 全部版本 | 把这些写法组合成一个新的设定，例如一个作表面、一个作内里，组合后要自洽 |

交给模型的素材文本示例（让 AI 选）：

```
- [物品功法] 神水（共 2 种写法）：有 2 种写法——①宗教圣物…；②狂信药剂…；标签：…
  ①宗教圣物（《耐瑟瑞尔的辉煌》）：教会祝福过的圣水，信徒饮用后会增加勇气，驱散恐惧。；作用：增加勇气、驱散恐惧；获取方式：教会祝福
  ②狂信药剂（《地狱公寓》）：邪教分发的药剂，饮者会丧失自我，成为狂信徒。；代价：丧失自我；作用：让饮者成为狂信徒
  （这是同一素材的不同写法：从中选一个最贴合当前设定的版本使用，不要把不同版本的设定混在一起）
```

- 请求里用 `materialVariants: {素材 id: "blend" | 成员 id}` 表示用户的选择（不传 = 让 AI 选）。Java 从成员素材里取各版本的概括和属性，交给 Python 按上面的格式写进提示词。
- 版本的独有设定和概括几乎一样时（短的那句 ≥70% 二元组出现在长的那句里）只写一次。
- **自动匹配**命中了某个版本时，自动按「只用这一版」处理（见 [素材检索](素材检索.md#7-ai-自动匹配素材)）。
- **复制进设定**（「从素材库添加」）：选了某一版 = 共性 + 那一版的概括、属性和详细；让 AI 选 / 融合 = 共性 + 「可选版本」逐条写进备注，由作者自己挑。
