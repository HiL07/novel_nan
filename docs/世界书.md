# 世界书：一个工作区的全部故事知识

> 相关代码：Python `app/generation/worldbook.py`（编译、局面快照）、`app/generation/facts.py`（账本的局面字段、定时事件）、
> `app/generation/prompts.py#digest_user`（每章抽取）；前端 `components/novel/WorldBook.vue`（工作区「世界书」页）。
> 接口：`GET /api/gen/novels/{id}/worldbook`。

## 1. 为什么要有世界书

AI 给后续走向时，好不好看不取决于设定写得多全，而取决于它能不能看清**此刻的局面**：谁想要什么、谁挡着谁、
未回收的伏笔、谁知道什么秘密、什么事快到期。以前这些散在四处，各自拼提示词：

- 设定编辑器的 spec（核心 / 卡片 / 后期才登场）
- 角色卡写进工作区的人物内核快照（`novel.personas`）
- 故事账本 `facts.json`（伏笔、角色状态、时间线）
- 故事阶段（阶段表 / 已写章数推算）、大纲、前情概要

而且旧的「后续走向」完全看不到账本，只看到最近 10 章摘要。评测里它的走向 89% 被挑出和已写内容矛盾（见 [走向引擎](走向引擎.md)）。

## 2. 编译，不另存

世界书**不单独存储**，每次从上面这些数据编译（`worldbook.compile(novel_id, chapter?)`，默认为下一章编译）：

| 条目来源 | 进世界书的样子 |
|---|---|
| spec 核心段落（世界观 / 情节 / 文风的普通字段） | `kind: rule`，常驻（pinned） |
| 主角（角色定位含「主角」）、主角的人物内核 | `kind: character`，常驻，`protagonist: true` |
| 其他角色卡、人物内核卡（同名合并成一条） | `kind: character`，提到名字 / 别名时才用 |
| 自定义元素（怪物、势力…）、情节节点 | `kind: element / event` |
| 出场条件没到的卡片 | 同上，`notYet: true` + `since`（只能作传闻 / 伏笔） |
| 账本里的角色（设定里没有的也算） | 并进同名人物条目的 `state` |
| 账本伏笔 / 定时事件 / 时间线 | `threads` / `clocks` / `timeline` |
| `inspire.stage_of` | `stage`（阶段 + 对手量级上限） |
| 大纲里接下来的章节、前情概要 + 最近 8 章摘要 | `outlineNext`、`story` |

改设定还是在「设定」页，改人物局面和伏笔还是在「故事账本」页；世界书页只读。
**不另存的原因**：多一份存储就多一份同步问题（改了设定世界书没变）；编译很快（只读几个 JSON），每次都是最新的。

## 3. 动态部分：人物局面和定时事件

账本里的角色原来只有 `state`（一句当前状态）。现在每条历史记录还可以带：

| 字段 | 含义 | 怎么算「当前值」 |
|---|---|---|
| `goal` | 他现在最想要什么（≤30 字） | 历史里最近一次写了的 |
| `obstacle` | 什么挡着他 | 同上 |
| `relations` | `[{to, rel}]` 和其他人物的关系（≤15 字） | 按对象合并，后写的覆盖 |
| `knows` | 他知道而别人不知道的关键信息 / 秘密 | 历史并集，最近 10 条 |

`clocks` = 定时炸弹（「三天后宗门大比」「月圆之夜毒发」）：`{chapter（定下的章）, text, due（期限）, status open|done, doneIn}`。

**来源**：
1. 每章写完的摘要调用（`chapter._digest`）多要这几个字段（没有就省略，`max_tokens` 900 → 1300）；
2. 老工作区 / 账本里还没有人物目标时，走向引擎第一次出走向前先「整理局面」（`directions.refresh_situation`，一次调用，
   按已写内容整理主要人物的 goal / obstacle / relations / knows 和 clocks），记成**最后一章的 AI 记录**（`facts.add_situation`，
   不清掉该章已有记录）。

**回滚规则不变**：这些字段都在 history 里，带章节号——删最后一章 `drop_from` 一起回滚（定时事件在被删的章里到期的重新打开），
重新提取某章 `drop_chapter` 一起替换；作者手动改过的角色（`manual`）保留作者的值，AI 只追加历史。
只更新了目标、没写状态变化的那章不会清空 `state`（取最近一条写了状态的）。

## 4. 局面快照

`worldbook.snapshot(wb, max_chars)` 把世界书压成走向引擎的输入（大模型 7000 字，本地模型 3500 字）：

```
【书名】（下一章是第 N 章）
【人物局面】主角在前，然后按最近有动静排，最多 10 人：名（定位）：状态｜想要｜阻碍｜关系｜知道
【未回收的伏笔】最近有动静的 12 条（带 F 编号）
【未到期的定时事件】
【故事阶段】阶段 + 对手量级上限
【大纲里接下来的章节】
【前情】前情概要 + 最近 8 章摘要（超长时只留最近 5 章）
【核心设定】常驻的规则段落
【其他设定】只列名字，尚未登场的标出来
```

工作区「世界书」页的「查看 AI 看到的局面」显示的就是这段文字。

## 5. 还没做的（P3 / P4）

- 写章节（`context.build`）、规划 / 一致性检查（`_plan` / `_review`）、AI 构思的其他功能、灵感墙绑定工作区时、试聊，
  目前还各自拼上下文，下一步统一改用世界书。调研时发现的不一致：试聊用 `spec.build` 而不是 `build_for`，
  所以会漏掉非主角的人物内核、也不按出场条件放行；`_plan` 用的是完整账本而 `_review` / `_digest` 用 `view_before`。
- 动态字段目前只在 `_digest` 和「整理局面」里写；故事账本页还不能手动编辑目标 / 关系 / 秘密（手动保存会保留它们）。
